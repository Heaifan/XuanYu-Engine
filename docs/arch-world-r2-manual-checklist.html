零、整体测试流程（操作手册，先读这一段）

本段告诉你“怎么测、按什么顺序测、测完怎么记录”。后面的 13 项是对照表，本段是总流程。

  1. 阶段 0 — 准备：确认仓库处于 refactor/ARCH-WORLD-layer-boundary 分支、版本串 v0.2.19.3-rz；确认 run.bat 指向 XuanYu.Editor.UI；在桌面建一个截图目录（如 R2-验收-日期），用来存 FAIL 证据。
  2. 阶段 1 — 启动与基线：双击 run.bat；观察终端先“编译”后“运行”，等待 Vulkan 初始化日志出现、视口（Viewport）窗口弹出、无红色报错。记录初始实体数量（层级面板中的条目数）。
  3. 阶段 2 — 先认结构：看左侧“层级面板（Hierarchy）”列出 N 个实体，右侧视口里也能看到对应 N 个物体；确认两者一一对应（名称能对上）。这一步不勾选，只是建立“面板↔视口”的对应关系认知。
  4. 阶段 3 — 按序测试（建议两轮）：
    • 第一轮 · 基础编辑闭环：①层级选择 → ②视口拾取 → ③移动预览 → ④移动提交 → ⑤取消拖动 → ⑥撤销 → ⑦重做。这 7 项构成“选→移→撤→重”最小闭环，先跑通。
    • 核心回归（重点盯防）：在第 ④ 项之后，立即验证“移动 A→B：旧位点不中、新位点得中；撤销回 A；重做回 B”三条（详见第七节）。这是 R2 的命门，建议每轮都先跑。
    • 第二轮 · 空间/视图/生命周期/一致性：⑧跨分区移动 → ⑨框选选中 → ⑩框选全部 → ⑪窗口缩放 → ⑫关闭释放 → ⑬创建删除一致性。最后压测一致性。
  5. 阶段 4 — 记录规范：每项 PASS 就勾选本页对应复选框；若 FAIL，必须：① 截当前视口图存入截图目录；② 写下复现步骤（先点哪、再拖哪、结果怎样）；③ 复制终端相关日志片段。三项缺一不算有效 FAIL。
  6. 阶段 5 — 汇总判定：13 项全部勾选后，到第九节“验收签署”填验收人/日期/结论。全部 PASS 即通知 AI 补 R2 CLOSED 收口；任一 FAIL 则按停手条件单独反馈，不要判 PASS。

通用操作约定：“点击”= 鼠标左键单击（不拖）；“拖动”= 左键按住移动再松开；“轴箭头”指位移控制器（Gizmo）上红(X)/绿(Y)/蓝(Z) 三个方向的箭头；“空白处”指视口中没有实体的区域。

一、基础交互（1–5）

1层级面板选择（Hierarchy）
前置编辑器已启动，左侧“层级面板（Hierarchy）”列出若干实体，右侧视口可见对应物体。
步骤
  1. 在层级面板中，用鼠标左键单击任意一个实体条目。
  2. 观察：该条目是否高亮？右侧视口中对应物体是否出现选中态（Gizmo 三轴箭头出现 / 描边变色）？
  3. 再单击面板中另一个实体条目，确认焦点从前者切到后者。
  4. 看右下/右侧“属性面板”是否刷新为当前选中实体的变换（位置/旋转/缩放）数值。
预期单击即选中对应实体；焦点切换干净（旧条目不再高亮）；属性面板同步显示该实体。
判定PASS：切换无残留旧选中、属性不错乱；FAIL：切到新实体后旧实体仍高亮，或属性显示的是别的实体。
溯源：SceneStateOwner 查询委托唯一 WorldQuery；层级面板与视口共享同一 GlobalWorld 真相层。
2视口拾取（Picking / Viewport）
前置场景中至少 3 个互不重叠、无遮挡争议的实体；默认透视视角；当前未处于任何拖动状态。
步骤
  1. 先在层级面板核对实体名称与视口里物体位置，做到“叫得出名、指得准位”。
  2. 把鼠标移到目标实体可见表面中心，注意避开它的 Gizmo 三轴箭头和选中描边环。
  3. 鼠标左键单击（单击，不要拖动）。
  4. 观察：该实体是否出现选中高亮？层级面板对应条目是否高亮？属性面板是否刷新？
  5. 再把鼠标移到另一个实体表面单击，确认焦点切换。
  6. 最后在视口空白处单击，确认选中被清除（或保持最后选中——按编辑器实际策略记录即可）。
预期点中哪个就选中哪个；无串选（点 A 不会选 B）、无漏选（点中却没反应）。
判定PASS：命中即所选、切换干净；FAIL：点 A 选中 B，或明明点中实体却选不中。
溯源：WorldSceneSingleAuthorityTests / Picking 回归 Moved_entity_hits_new_position_not_old_position。占位工厂为实体显式 ±0.5（实体自身 Bounds，情况 A）。
3移动预览（Move Gizmo Preview，拖拽中不提交）
前置已在层级面板选中某实体；视口中出现位移控制器（Gizmo）：中心方块 + 红(X)/绿(Y)/蓝(Z) 三轴箭头。
步骤
  1. 把鼠标移到 X 轴红色箭头上，光标应变双向箭头形状（表示可沿 X 拖动）。
  2. 按住左键，缓慢向右拖动约 2 个网格间距，眼睛盯着实体：它是否实时跟着光标走？
  3. 停在半路不要松开，此时去翻“操作历史 / 撤销栈”（若编辑器有此面板），看是否已经多了一条移动记录——应当还没有。
  4. 确认预览位置与光标贴合，无明显偏移或跳变。
预期拖动过程中实体实时预览跟随；此时撤销栈不应新增记录（预览未提交到真相层）。
判定PASS：预览与提交分离清晰、跟随顺滑；FAIL：一拖动就直接落定（没有预览阶段），或预览位置与实际落点不符。
溯源：R2 不动预览语义（R4 事务）；仅收口查询权威，预览仍走原路径。
4移动提交（Move Gizmo Commit，释放后落实）
前置接上一项，实体正处在拖动预览中。
步骤
  1. 把实体拖到新的目标位置（与起点明显分开，便于后续验证），松开左键。
  2. 看实体是否停在新位置（不回弹）。
  3. 看层级面板 / 属性面板：该实体的位置数值是否更新为新坐标。
  4. 打开“操作历史 / 撤销栈”，确认新增了一条移动记录。
预期释放即落定；变换数值更新；撤销栈多一条，且可对该条做撤销。
判定PASS：落定且可撤销；FAIL：松开后回弹/落点偏移/撤销栈无新记录。
溯源：GlobalWorld.UpdateTransform 是唯一写链；提交经 GlobalWorld→WorldQuery 同步索引。
5取消拖动（Esc Cancel，放弃拖动）
前置选中实体并进入了拖动预览（参考第 3 项操作到“按住拖动”状态）。
步骤
  1. 把实体拖到一个明显偏离原位置的地方（不松开）。
  2. 按下键盘 Esc 键。
  3. 观察：实体是否瞬间回到拖动前的位置？
  4. 检查撤销栈：不应因为这次取消而产生新记录。
  5. 确认 Gizmo 仍在，可再次拖动（取消不等于锁定）。
预期按 Esc 后完全还原到拖动前；无脏记录；控制器可继续使用。
判定PASS：取消后完全还原；FAIL：实体留在偏离位，或取消动作本身生成了一条废记录。
溯源：R2 不重构撤销/取消语义，仅验证查询权威下取消行为未被破坏。

二、撤销 / 重做（6–7）

6撤销（Undo，恢复上一位置）
前置已对实体做过一次“移动提交”（第 4 项），实体现在处于新位置 B。
步骤
  1. 触发撤销：编辑器菜单“编辑→撤销”，或快捷键（通常是 Ctrl+Z），或工具栏撤销按钮。
  2. 观察实体：是否回到移动前的旧位置 A？
  3. 在旧位置 A 处单击：应能选中（HIT）。
  4. 在原目标位置 B 处单击：应选不中（MISS）。
预期撤销后位置与拾取同步回退到 A；点 A 命中、点 B 落空。
判定PASS：位置回退且拾取跟随；FAIL：位置回了 A，但点 B 仍能选中（说明索引没跟着回退）。
溯源：WorldSceneSingleAuthorityTests 撤销重做用例；索引由 GlobalWorld 写链统一回退。
7重做（Redo，重做下一位置）
前置接上一项，已撤销，实体回到旧位置 A。
步骤
  1. 触发重做：菜单“编辑→重做”，或快捷键（通常 Ctrl+Y / Ctrl+Shift+Z），或工具栏重做按钮。
  2. 观察实体：是否回到撤销前的目标位置 B？
  3. 在位置 B 处单击：应能选中（HIT）。
  4. 在旧位置 A 处单击：应选不中（MISS）。
预期重做后位置与拾取再次前移到 B；点 B 命中、点 A 落空。
判定PASS：重做后拾取跟随；FAIL：位置恢复 B，但点 A 仍能选中。
溯源：同第 6 项；重做经同一权威写链重放。

三、空间跨度（8）

8跨分区移动（跨 Region，旧区无残留）
前置若编辑器能显示空间分区（Region）边界，请开启分区可视化；确保场景至少 2 个相邻分区 R1、R2。
步骤
  1. 选中一个位于分区 R1 内的实体，记下它的当前位置（记为 A，在 R1）。
  2. 用 Gizmo 把它拖入相邻分区 R2 并“移动提交”（参考第 3/4 项）。
  3. 回到分区 R1 的原位置 A 处单击：应选不中（MISS，旧区无残留）。
  4. 在分区 R2 的新位置 B 处单击：应能选中（HIT）。
  5. 在层级面板确认该实体仍只有一条记录（没有 R1、R2 各一份的重复）。
预期实体只存在于 R2 坐标；R1 不再返回它（查询/射线均无）；无双份、无幽灵。
判定PASS：跨区后查询与拾取全局一致；FAIL：旧区 R1 仍能拾取，或新区 R2 无响应。
溯源：WorldSceneSingleAuthorityTests 跨分区用例；删除场景第二索引后，全局唯一索引保证无分区镜像残留。

四、视图（9–10）

9框选选中（Frame Selected，居中选中的实体）
前置选中某个偏离视口中心的实体（可先用第 1 项选中）。
步骤
  1. 触发“框选选中（Frame Selected）”：菜单 / 快捷键 / 或在层级面板双击该实体（按编辑器实际入口操作）。
  2. 观察相机：是否平移+缩放，使该实体居中且适配视野？
  3. 框选完成后，在该实体上单击：仍能正确选中（HIT）。
  4. 注意：点击位置与实体落点是否吻合（没有因为相机动了而点偏）。
预期居中后实体清晰可见且拾取坐标映射正确；点击不偏位。
判定PASS：居中后拾取准确；FAIL：居中后点击偏位（说明查询/投影未随相机同步）。
溯源：R2 不改动相机/投影；验证唯一权威下相机联动拾取无回归。
10框选全部（Frame All，适配所有实体）
前置场景中存在多个分散实体（最好横跨不同分区，以增强覆盖）。
步骤
  1. 触发“框选全部（Frame All）”。
  2. 观察相机：是否缩放/平移到能完整容纳所有实体的视野？
  3. 逐个在分散的实体上单击：每个都应能正确选中（HIT）。
  4. 确认没有实体被裁出视野之外或点击错位。
预期全部实体进入视野且拾取一致；遍历点击无遗漏、无错位。
判定PASS：全部可见且拾取一致；FAIL：部分实体看不见，或某实体点击错位。
溯源：本轮补项（修正原“13 项/实列 11 项”不一致）；验证全局索引遍历完整性。

五、生命周期（11–12）

11窗口缩放与交换链重建（Resize / Swapchain）
前置编辑器运行中，视口里有实体。
步骤
  1. 用鼠标拖拽窗口右边框 / 下边框，由小拖大、由大拖小，反复多次（含拖到很窄、很宽的极端比例）。
  2. 点击窗口“最小化”再“恢复”。
  3. 若编辑器支持，切换一次显示分辨率。
  4. 每次尺寸变化后，在实体上单击验证拾取：点中位置与实体落点是否一致？
  5. 盯住终端：是否有 Vulkan 校验层（validation layer）红色报错、黑屏、或卡死。
预期交换链（Swapchain）重建无崩溃、无黑屏、无校验报错；重建后拾取坐标映射仍正确。
判定PASS：多次缩放后功能正常、拾取不偏；FAIL：某次缩放后黑屏/崩溃/拾取错位。
溯源：Render.Vulkan 生命周期（VK3–VK5 已封版）；R2 仅确保查询层不依赖窗口尺寸，验证无回归。
12关闭生命周期释放（关闭窗口干净退出）
前置编辑器已运行并完成若干操作（最好刚跑过移动/缩放等）。
步骤
  1. 点击窗口右上角“关闭（X）”。
  2. 盯住启动 run.bat 的那个终端窗口：有无异常堆栈、报错信息？
  3. 确认进程已退出（终端回到命令提示符，或任务管理器里该进程消失）。
  4. 留意有无“资源未释放 / 内存泄漏”类告警。
预期Vulkan 资源依次释放、无悬挂渲染线程、无内存泄漏告警；退出码正常。
判定PASS：干净退出；FAIL：退出时报错/卡死/资源泄漏告警。
溯源：VK-LIFE 系列已封版（P1 待办未启动，但关闭路径应无回归）；R2 不涉及资源释放改动。

六、一致性（13）

13创建与删除后拾取一致（Create / Destroy）
前置空场景或仅少量实体。
步骤
  1. 新建一个实体 → 立即在它身上单击：应能选中（HIT，无延迟）。
  2. 删除该实体 → 立即在原位置单击：应选不中（MISS，无幽灵残留）。
  3. 重复“新建→删除”至少 5 次，每次都做上面的命中/落空验证。
  4. 最后再新建一个实体，确认仍能立即拾取命中。
  5. 观察层级面板：实体数量应随增删实时增减，无“删了还在列表里”的幽灵条目。
预期每次增删后，空间查询与拾取立即反映；无幽灵、无遗漏；反复操作不退化。
判定PASS：增减即同步；FAIL：删了仍能拾取（幽灵），或新建了却拾取不到。
溯源：WorldSceneSingleAuthorityTests 创建删除用例；唯一写链保证增删即时进/出全局索引。

七、重点盯防（R2 核心价值，必须逐条人工确认）

① 移动 A→B（验证“场景第二索引已死”）：把实体从位置 A 拖到 B 并提交后——在旧 A 位置单击必须选不中（MISS），在 B 位置单击必须选中（HIT）。这是证明“查询统一走 GlobalWorld→WorldQuery、场景不再维护第二份索引”的关键。

② 撤销跟随：撤销后，在 A 位置单击必须命中、在 B 位置单击必须落空。

③ 重做跟随：重做后，在 B 位置单击必须命中、在 A 位置单击必须落空。

这三条任一失败，说明索引没跟着真相层同步回退，立即按停手条件单独报告，不要判 PASS。建议放在第一轮第 ④ 项之后立即验证（见零节“核心回归”）。

八、A / B 实体尺寸差异探针

语义背景（已由自动测试证明）：WorldEntityBoundsSemanticsTests 已验证两极——

  • A 类（默认）：Extent = default → Min==Max==Position，零尺寸点状空间足迹（并非“无空间信息”）。
  • B 类（显式）：实体自带 ±0.5 本地盒 → 绝对盒如 (9.5,-0.5,-0.5)/(10.5,0.5,0.5)。

真机侧验证策略：图形界面默认创建的实体，经占位工厂显式给 ±0.5（属“实体自身 Bounds，情况 A”，不是 WorldQuery 发明的通用尺寸）。所以真机默认实体都是 B 类。只要第 ②/⑧/⑬ 项里 B 类实体“移动后拾取精确跟随”，就间接证明 WorldQuery 只消费真实 Bounds、没偷偷发明统一 1×1×1 尺寸。

可选增强（超出 R2 范围，已登记）：若想肉眼确认“A 类零尺寸点极难命中”以彻底排除任何统一尺寸残留，需在编辑器侧加调试入口构造零尺寸点实体——属 R4 编辑器污染剥离的关注点，不在本论。当前以自动测试 + B 类真机行为为准。
