# WORLD-C-R0 场景文档契约冻结

版本：v0.2.21.1-rz

阶段：WORLD-C-R0：场景文档契约

## 裁定

WORLD-C 的目标是把编辑器从“只能操作启动时预置的测试实体”推进到“用户能够创建、修改、保存、关闭并重新打开自己的场景”。

R0 只冻结场景文档、状态机、错误模型和模块边界，不实现完整保存/打开运行时代码，不加入资产数据库、Prefab、通用组件序列化、模型导入、材质、动画、热重载、云同步或项目管理器。

## 场景文件

- 扩展名：`.xyscene`。
- 格式：UTF-8 JSON。
- Schema 版本字段：`schemaVersion`，首版固定为 `1`。
- 最小元数据：`name`、`createdUtc`、`modifiedUtc`、`entities`。
- 原子保存：写入同目录临时文件，完整 Flush 成功后替换正式文件；替换失败不得丢弃当前运行态。

最小示例：

```json
{
  "schemaVersion": 1,
  "name": "Untitled",
  "createdUtc": "2026-07-31T05:48:34Z",
  "modifiedUtc": "2026-07-31T05:48:34Z",
  "entities": [
    {
      "id": "entity-1",
      "name": "Entity 1",
      "parentId": null,
      "position": { "x": 0.0, "y": 0.0, "z": 0.0 },
      "rotation": { "x": 0.0, "y": 0.0, "z": 0.0 },
      "scale": { "x": 1.0, "y": 1.0, "z": 1.0 }
    }
  ]
}
```

## 所有权

- 未来 `XuanYu.Editor.SceneDocument` 拥有场景文档读写契约、状态机和错误结果。
- `XuanYu.World` 继续拥有运行期 `GlobalWorld / EntityRegistry / Transform` 事实。
- 文档加载只通过明确导入步骤重建或更新 World 运行态；保存只从 World 当前事实与 Editor 文档元数据生成文件快照。
- `XuanYu.Editor.UI` 只发起新建、打开、保存、另存为和关闭意图，不得成为持久化权威。
- 禁止出现“文件副本”和“World 运行态”互相覆盖的双权威；同步必须有单次事务边界和明确结果。

## 实体字段

R0 只冻结以下实体数据：

- 稳定实体 ID。
- 名称。
- `parentId` 或根节点 `null`。
- Position。
- Rotation。
- Scale。

禁止在 R0 加入通用组件反射、任意组件序列化、Prefab、脚本序列化或资产引用系统。

## 状态机

```text
Untitled
  新建但没有保存路径

Clean
  当前运行态与最后一次保存成功的文件一致

Dirty
  World 或文档元数据发生可保存修改

Saving
  正在写临时文件并准备替换正式文件

Loading
  正在解析并验证场景文件

Failed
  上一次新建、打开、保存、另存为或关闭前检查失败
```

Dirty 来源包括实体创建、删除、重命名、父子关系变化、Position / Rotation / Scale 变更和场景名称变化。保存成功后进入 `Clean`；保存失败保持 `Dirty`，并返回错误结果。打开其他场景或关闭当前场景前，若为 `Dirty`，必须先给 UI 明确的未保存处理结果入口。

## 错误模型

R1 起必须显式返回以下错误，不得静默失败或自动覆盖当前场景：

- 文件不存在。
- 文件不可读。
- JSON 或文档结构损坏。
- 格式版本不支持。
- 实体 ID 重复。
- 层级引用不存在。
- 层级循环。
- Transform 数据非法。
- 保存路径不可写。
- 写入失败。

错误结果必须包含错误分类、用户可见中文消息和安全恢复状态。

## R1 入口

WORLD-C-R1 的最小验收链：

```text
启动编辑器
→ 打开测试场景
→ 移动、旋转或缩放实体
→ 保存场景
→ 关闭编辑器
→ 重新启动
→ 打开刚才保存的场景
→ 实体身份、名称、层级和 Transform 完整恢复
```

R1 同时覆盖新建、打开、保存、另存为、未保存状态提示、切换场景前的未保存处理、损坏或不支持文件的明确报错，以及保存成功后恢复 Clean。
