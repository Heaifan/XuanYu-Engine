# WAVE-2.5-B Unified Cancellation Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 建立平台无关的 Viewport Gesture Begin/Update/Commit/Cancel 生命周期，统一取消原因、上下文、顺序、幂等性和清理信号。

**Architecture:** `ViewportGestureLifecycle` 保留当前 Gesture Context，只有 Active 状态才允许 Update、Commit 或 Cancel。Cancel 先把仍然有效的 Context 传给 Consumer，再发出 Capture release 和 temporary-state cleanup，最后将生命周期恢复为 Idle；重复或无 Owner 的终止调用返回 no-op 结果。

**Tech Stack:** C#、`XuanYu.Editor` platform-neutral records/interfaces、xUnit tests in `XuanYu.World.Tests`。

**Spec:** `docs/superpowers/plans/2026-09-24-wave-2.5-b-cancellation-lifecycle.md`

## Global Constraints

- 只修改 Lifecycle contract、Lifecycle tests、审计文档和本执行计划。
- 禁止迁移 Camera、Picking、Gizmo、Region、Road、Marker、Snap。
- 禁止修改 Router、Native/Avalonia adapter、Win32、Vulkan、Renderer、Composition。
- Lifecycle core 不引用 Avalonia、Win32、Vulkan 或 Diagnostic。
- 5+100：手写 `.cs` 单文件不超过 100 行。

## Review Focus

- Cancel callback 必须看到原始 Gesture Context：由取消测试断言 Consumer 收到 Owner、Pointer、Capture 和输入状态。
- Cancel 必须先通知 Consumer、再释放 Capture、再清理临时状态：由顺序记录测试断言。
- 重复 Cancel、无 Owner Cancel、Cancel 后 Released/Commit 都必须 no-op：由 exactly-once 测试断言。
- Terminal 后必须允许新 Begin：由重新开始测试断言。
- 所有目标原因必须归一到同一枚举：由 reason matrix 测试断言。
