# WAVE-2.5-E Production Input Unification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 run.bat 的 Native/Avalonia 真实生产输入统一接入 `EditorPointerEvent -> ViewportInputRouter -> GestureOwner -> Consumer -> ViewportGestureLifecycle`。

**Architecture:** 保留平台 source 与 adapter 的边界；Composition Root 装配单一 Router、Coordinator 和 consumer set。Host/Window 只转换来源事件，VM 输入方法只作为 consumer/backend 执行核心。

**Tech Stack:** C#, Avalonia, Win32 WndProc, existing `XuanYu.Editor.Input` contracts, xUnit, run.bat runtime gate.

**Spec:** `docs/superpowers/specs/WAVE-2.5-E-Production-Input-Wiring-Spec.md`

## Global Constraints

- 所有手写 `.cs` / `.axaml` / `.js` 单文件 ≤100 行。
- `Editor.UI` 不得直接依赖 Vulkan 实现；`Render.Abstractions` 不得引用 `Silk.NET.Vulkan`。
- 高频 PointerMoved/Hover/DragPreview/RenderFrame 不得新增可预见的大规模 O(N) 扫描或重型副作用。
- Diagnostic 只能旁路观察，不进入 Production Arbitration。
- Native/Avalonia 可以有不同平台 capture，但只能有一个业务生命周期 owner。
- 不修改 Schema，不引入新依赖，不修改 FIX10 禁区文件。

## Review Focus

- Native 与 Avalonia 同一手势不得同时开始两个 owner：Task E2/E3 的 convergence tests。
- Native capture loss 与 Avalonia capture loss 只能触发一次 cancel/release：Task E5 的 idempotency tests。
- idle wheel 不得被活动 pointer owner 错误消费：Task E4 的 wheel tests。
- Tool/Mode/Window/Dispose 在 active gesture 中必须清理旧 owner：Task E5 的 lifecycle tests。
- Diagnostic observer 不得改变 Router 结果：Task E7 的 observer isolation test。
