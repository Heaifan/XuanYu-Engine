## Goal

收口 Native Win32 与 Avalonia 输入在 Source/Adapter 边界的语义差异，使“等价物理操作”能够生成等价的 `EditorPointerEvent`。

本任务只允许修 Source/Adapter parity，不接入统一 Router，也不改变业务 Consumer ownership。

## Required parity

必须审计并覆盖：

- Left Down/Up
- Right Down/Up
- Middle Down/Up
- Move
- Wheel positive / negative
- Shift
- Ctrl
- Alt
- button state
- pointer logical position
- DPI 1.0 / 1.25 / 1.5 / 2.0
- PointerId contract
- SourceSurface
- logical vs physical coordinate boundary

## Known GAP to close

### 1. Win32 Right Button forwarding

当前 `NativePointerMessage` / Adapter 已认识 RightDown/RightUp，但 `Win32ViewportHost.Input.cs` 未转发 `WM_RBUTTONDOWN/UP`。

必须补齐 Source forwarding。

注意：

- 不得顺手改变右键业务含义。
- 不得因为转发右键而让 Camera/Picking/Gizmo 获得新的行为。
- Native capture policy 是否包含右键必须以当前产品行为为准；没有现有证据时保持当前 capture policy，不自行扩张。

### 2. Wheel coordinate semantics

审计 Win32 `WM_MOUSEWHEEL` 的坐标空间。

必须证明进入 `EditorPointerEvent.Position` 前已经转换为 viewport logical/DIP。

如果现有路径把 screen coordinate 当 child-client coordinate，必须在 source boundary 修正，并提供正反测试。

不得把 DPI/坐标二次转换推给 consumer。

### 3. Wheel delta

验证正负 wheel delta 的 signed semantics。

`120 native units = 1 logical notch`。

### 4. Modifier parity

Native 与 Avalonia 对：

- Shift
- Ctrl
- Alt

生成的 `EditorPointerModifiers` 必须一致。
