# WAVE-2.5-B Unified Cancellation Lifecycle Audit

基线：`564036a525e13101210277e418afc1f1f0df9e4a`

任务书冻结：`ad1f3083f0ec64bdb0c90a9f3045fa60c2707721`

本轮建立平台无关的生命周期协议，不迁移具体 Viewport Consumer。

## 统一协议

### State

```text
Idle --Begin--> Active
Active --Update--> Active
Active --Released/Commit--> Idle (Committed)
Active --Cancel(reason)--> Idle (Canceled)
```

`ViewportGestureLifecycle` 保留当前 `ViewportGestureContext`，Context 包含：

- Gesture 名称
- Gesture Owner
- PointerId
- Capture 类型
- 当前 `EditorPointerEvent`，包括位置、Buttons、Modifiers、DPI 和 SourceSurface

`IViewportGestureConsumer` 冻结四个入口：

```text
Begin(context)
Update(context)
Commit(context)
Cancel(ViewportCancellationContext)
```

Cancel Context 同时携带原始 Gesture Context 与统一 `ViewportCancellationReason`。

### Cancel Reason

| Trigger | Unified reason | Terminal result |
|---|---|---|
| ESC | `Escape` | Canceled |
| Pointer Capture Lost | `CaptureLost` | Canceled |
| Focus Lost | `FocusLost` | Canceled |
| Window Deactivate | `WindowDeactivated` | Canceled |
| Tool switch | `ToolChanged` | Canceled |
| Mode switch | `ModeChanged` | Canceled |
| Viewport dispose/detach | `ViewportDisposed` | Canceled |
| Platform interruption | `PlatformInterrupted` | Canceled |
| Explicit API cancel | `ExplicitCancel` | Canceled |
| Pointer release / normal end | not a cancel reason | Committed |

不同 Consumer 不再需要自行定义取消字符串或互不兼容的枚举。

### Cancel Pipeline

统一顺序固定为：

```text
Cancel Trigger
→ Lifecycle.Cancel(reason)
→ Consumer.Cancel(context + reason)
→ ReleaseCapture(context)
→ ClearTemporaryState(context)
→ Current = None
→ State = Idle
```

Consumer 在收到 Cancel 时仍能读取正在取消的 Gesture、Owner、Pointer、Capture 和输入状态。Lifecycle 在终止后返回 `CaptureReleased`、`TemporaryStateCleared` 与 `Terminal` 结果。

错误顺序被禁止：先清空 Current/Owner，再通知 Consumer。

Cancel、Release、Commit、Dispose 的含义分别是：

- Cancel：放弃当前 Gesture，不产生正常提交。
- Release：释放 Capture 的清理动作，不代表 Commit。
- Commit：正常完成 Gesture，可产生 Consumer 的正式结果。
- Dispose：Viewport 生命周期结束；通过 `ViewportDisposed` 进入 Cancel，不等同于 Commit。

## Existing Consumer Audit

| Consumer | Existing cancel entry | Required unified connection | Status |
|---|---|---|---|
| Camera | `CancelCameraNavigation(reason)`；Native/Avalonia/Window path 分散 | Consumer.Cancel + release + clear | GAP |
| Transform Gizmo | `CancelInteraction*`；EditorState 直接清空 | 保留 Context 后调用统一 Cancel | GAP |
| Navigation Gizmo | Host `CancelNavGizmo` | 移入唯一 Gesture Owner | GAP |
| Region | `CancelRegionDrawingFromEscape`、CaptureLost 部分路径 | Window/Focus/Dispose 全部归一 | GAP |
| Road | `CancelRoadDrawingFromEscape`、CaptureLost 部分路径 | Window/Focus/Dispose 全部归一 | GAP |
| Marker | 当前为立即放置，尚无统一 drag lifecycle | 后续 Consumer contract 接入 | GAP |
| Map Geometry | `CancelMapGeometryPointer(reason)` | 统一 Context 与 temporary cleanup | GAP |

现有入口与统一协议的关系：

```text
ESC / CaptureLost / FocusLost / Window Deactivate /
Tool switch / Mode switch / Dispose / Platform interrupt / Explicit cancel
→ 当前各自的 UiVm/Host cancel 字符串与方法
→ 本轮提供统一 Lifecycle contract
→ 后续 D1/D2 Consumer migration 才能接入同一 Consumer.Cancel
```

本轮不修改这些旧入口，避免启动 Production Viewport Migration。

## Test Evidence

`ViewportGestureLifecycleTests` 与 `ViewportGestureTerminalTests` 覆盖：

- 九种统一 Cancel Reason。
- Begin、Update、Commit、Cancel 四阶段。
- Cancel Context 保留原始 Owner、Pointer、Capture、Input。
- Cancel 通知顺序：Consumer → ReleaseCapture → ClearTemporaryState。
- Cancel 后 State=Idle、Current=None、Capture/Temporary cleanup 均 exactly once。
- 重复 Cancel、无 Owner Cancel、Cancel 后 late Commit 均为安全 no-op。
- Commit 不调用 Consumer.Cancel。
- Commit 后下一次 Begin 可成功。

## 明确边界

- 未修改 Camera、Picking、Gizmo、Region、Road、Marker、Snap 生产行为。
- 未修改 `VulkanNativeHost`、`Win32ViewportHost`、Native/Avalonia Adapter、Router 或 Owner。
- 未修改 Renderer、Vulkan Composition、Composition Root 或 UI 输入入口。
- 未删除 NativeControlHost、Win32 bridge 或既有 Native input path。
- 未启动 WAVE-3。
- Lifecycle core 无 Avalonia、Win32、Vulkan、Diagnostic 依赖。

本报告只证明统一 Cancellation Lifecycle 基础设施已经具备，不代表任何具体 Consumer 已完成 Production Migration。
