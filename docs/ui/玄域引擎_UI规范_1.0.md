# 1. 文档身份与适用范围

## 1.1 性质

本规范是玄域引擎全部 UI 的**强约束默认标准**，不是参考建议。开发、测试、审计、验收与治理活动均以本规范为执行依据。

## 1.2 适用范围

- 玄域引擎编辑器（主窗口、顶部菜单与工具栏、顶层页签、层级树、检查器、地图编辑器、图层面板、底部日志与通知）；
- 检查器、偏好、模式、调试等现有及后续页签；
- 日志、调试工具、开发者控制台；
- 启动器、安装器；
- 游戏内开发和调试工具；
- 《兵无常势》正式游戏 UI（受第 16 节边界约束）。

## 1.3 生效基线

本规范发布时，MAP-A-R2-D4-F3 已落地的局部 UI 合同（顶层页签字号、状态图标配色与热区、类型标签配色、拖动插入线、事务式拖动、通知优先级、技术日志保留）全部收敛入本规范对应章节；`docs/ui/玄域引擎_旧UI审计矩阵.md` 中 W01~W71、G01~G08、K01~K07 为整改追踪清单，以本规范为整改目标。

## 1.4 治理层级与文档优先级

本规范是 **UI 设计规则领域内的唯一事实源**，不高于项目的代码宪法与工程治理规则。治理层级固定如下：

```text
第一层：AI 开发宪法
第二层：CODE_CONSTITUTION.md、AI_DEVELOPMENT_RULES.md、dev-rules.md，
       以及各自职责范围内已冻结的架构合同、领域合同和持久化合同
第三层：玄域引擎 UI 规范 1.0（UI 设计规则领域内唯一事实源）
第四层：阶段治理计划（如 ARCH-UI-SPEC-R1 实施计划）
第五层：阶段局部 UI 合同与页面实现说明
```

规则：

1. 本规范不得覆盖第一、二层规则；
2. 第二层文件之间发生跨领域冲突时，本规范不得擅自裁定其相互优先级，必须停止实施并上报用户；
3. 本规范与第一、二层规则冲突时，必须停止实施并上报用户，不得自行选择；
4. 阶段治理计划与阶段局部 UI 合同不得覆盖本规范；
5. 局部合同与本规范冲突时，以本规范为准，除非存在已批准的受控例外（第 20 节）。

# 2. 规范优先级与条款分级

## 2.1 三级条款

| 等级 | 含义 | 执行要求 |
|---|---|---|
| 必须 | 项目统一底线 | 违反即不得验收 |
| 应当 | 默认设计方案 | 偏离时必须说明理由并经过审查 |
| 可以 | 规范允许的选择 | 只能在规定范围内选择 |

## 2.2 禁止的放行理由

开发者不得以「视觉偏好」「局部方便」「实现简单」「与本轮无关」「已有代码如此」为由跳过规范。

## 2.3 例外机制

专业界面无法适用通用规则时，按第 20 节《受控例外》申请；页面开发者不能自行宣布例外。

# 3. 字体与字号

## 3.1 字体回退链（必须）

```text
Microsoft YaHei UI → Segoe UI → Noto Sans CJK SC → 系统无衬线字体
```

- Avalonia 实现：`FontFamily="Microsoft YaHei UI, Segoe UI, Noto Sans CJK SC"`；
- 「系统无衬线字体」由 Avalonia 平台默认回退承担，不额外指定字体名；
- 禁止使用 `Inter` 及任何未登记字体；
- 等宽字体仅限日志/数值列（组件级例外，见第 19 节允许清单）；
- 正式游戏 UI 允许独立品牌字体（第 16 节），缺字必须自动回退到本链。

## 3.2 字号 Token（必须）

| Token | 字号 | 标准行高 | 用途 |
|---|---:|---:|---|
| `Font.Meta` | 10 DIP | 14 DIP | 类型标签、极次要元信息 |
| `Font.Small` | 11 DIP | 16 DIP | 辅助文字、次级状态 |
| `Font.Label` | 12 DIP | 18 DIP | 字段标签、按钮文字、菜单辅助信息、**列头/表头** |
| `Font.Body` | 13 DIP | 20 DIP | 正文、字段值、树、列表、日志正文 |
| `Font.Section` | 14 DIP | 22 DIP | 二级页签、**分组标题** |
| `Font.Title` | 16 DIP | 24 DIP | 面板主标题、弹窗标题 |
| `Font.Page` | 20 DIP | 28 DIP | 欢迎页与页面标题 |
| `Font.Display` | 24 DIP | 32 DIP | 启动器或大型结果标题 |

用途约束（必须）：顶层页签 13；地图编辑器二级页签 14；字段标签 12；字段值 13；普通按钮 12；类型标签 10～11；普通编辑器区域禁止响应式缩放字号。

## 3.3 分组标题裁决（D1 审订定稿）

- 面板内**分组标题**（「基础信息」「地图资产」「图层属性」等）统一 `Font.Section=14 DIP` + SemiBold；
- **列头/表头**（日志表头、表格列头等）属于紧凑列表元信息，使用 `Font.Label=12 DIP` + SemiBold；
- 废止 D4-F3 旧合同「分组标题 13 半粗」；现状 `TextBlock.section` 的 12 分组长按本节迁移至 14；
- 同一界面内分组标题与列头必须可区分：分组标题 14、列头 12，两者不得混用。

## 3.4 字重体系（必须）

| 字重 | 适用范围 |
|---|---|
| `Regular` | 正文、字段值、说明、日志正文、普通按钮 |
| `Medium / SemiBold` | 页签（顶层与二级）、分组标题、选中项、重点按钮、菜单栏、列头 |
| `Bold` | 页面主标题、弹窗标题、关键结果、严重状态 |

- 禁止 `Light`；品牌场景确需时按第 20 节申请例外；
- 页面不得新增任何字重等级。

## 3.5 行高实现（D1 审订定稿）

- 字号 Token 与标准行高**组合定义**（每个字号固定绑定标准行高，见 3.2 表）；
- 标准行高只用于**多行文本**（正文、说明、帮助、长文本、日志详情）；
- **单行控件**（按钮、输入框、树行、列表行、日志行、页签）的行高由控件高度 Token（第 6 节 24/28/32）决定，`LineHeight` 不机械套用正文行高，避免垂直错位；
- 多行文本框（如日志详情体）最小高度按「行高 × 行数 + 内边距」计算，禁止写死魔法值。

# 5. 间距、尺寸、圆角

## 5.1 间距网格（必须）

主网格：`4 / 8 / 12 / 16 / 24 / 32 DIP`；受控半级：`2 / 6 DIP`。其他数值禁止随意使用。

## 5.2 内边距档位（必须）

| 档位 | 值 | 适用 |
|---|---|---|
| 紧凑 | `6×2 DIP` | 工具栏小按钮、列表内操作、图标按钮、图层工具按钮 |
| 标准 | `8×4 DIP` | 普通按钮、输入框、菜单项、信息块 |
| 宽松 | `12×6 DIP` | 弹窗主操作、欢迎页关键按钮 |

页签、菜单项、图标按钮等稳定组件允许建立组件级 Padding Token（如页签 `10,4`、层标签 `5,1`），但必须登记（第 19 节）。

## 5.3 固定宽度等级（必须）

`64 / 96 / 128 / 160 / 240 DIP`。

- 检查器标签列默认 `96`；字段最小宽度 `128`；
- 按钮宽度由文字、图标和标准内边距决定，不强制固定等级；
- **不属固定宽度等级的项**（登记为组件 Token 或允许清单，不受宽度等级检查）：表格列宽（含日志列宽 `4/72/56/72/92/*/82`）、图标与热区尺寸、分隔条（6 DIP）、动态布局列（`*`、`Auto`）、树形缩进（16 DIP 级）；
- 现状历史值 `52`（全局 Button MinWidth）撤销：按钮最小宽度由热区合同（第 6.3 节）与内边距决定；
- 现状 `70/90` 标签列统一迁移至 `96`（审计矩阵 W44/W48/W53）。

## 5.4 圆角（必须）

| 级别 | 值 | 适用 |
|---|---|---|
| 小圆角 | `3 DIP` | 类型标签、层类型标签、细装饰标记 |
| 标准圆角 | `6 DIP` | 面板、信息块、输入框、普通按钮、工具栏按钮、页签（顶层与二级）、菜单项、Tooltip、弹窗、树行、搜索框、状态胶囊 |
| 大圆角 | `10 DIP` | 欢迎页、启动器、游戏 HUD 等大块视觉容器 |

- 编辑器主体只使用 3～6；禁止大量胶囊形按钮；圆形控件只用于明确语义对象（状态圆点、选中标记）；
- 现状越界值迁移目标：`4/5/7/9 → 6`（工具栏按钮、页签、树行、状态胶囊、信息卡）；日志行级别圆点与拖动插入线为组件例外（圆角取元素尺寸一半或 `1`，登记允许清单）。

# 6. 控件高度与点击热区

## 6.1 控件高度三档（必须）

| 档位 | 值 | 适用 |
|---|---|---|
| 紧凑 | `24 DIP` | 工具栏小按钮、列表内操作、图标按钮、搜索框 |
| 标准 | `28 DIP` | 输入框、下拉框、普通按钮、树行、列表行、日志行 |
| 强调 | `32 DIP` | 弹窗主操作、菜单项、页签、图层行、工具栏命令按钮 |

## 6.2 现状迁移目标（D1 审订定稿）

| 现状 | 迁移目标 | 依据 |
|---|---|---|
| `ListBoxItem` 34（全局） | 28 | 标准列表行 |
| `kvRow` 30 | 28 | 标准行 |
| `layerTool` 25 | 24 | 紧凑工具栏按钮 |
| `sideTab` 30 | 32 | 页签属强调档 |
| `detailBody` 42 | 按行高公式计算 | 多行文本框属内容最小高度，不设档位 |
| 其他 30/25/34 类值 | 按用途归入 24/28/32 | 本表同规则 |

## 6.3 高度语义区分（必须）

- **控件高度**：24/28/32 三档，用于交互控件；
- **内容最小高度**：由内容数量与行高推导（如多行文本框 `行高 × 行数 + 内边距`），不设档位、禁止魔法值；
- **复合容器高度**：由子元素尺寸与间距之和决定（如日志面板、页签内容区），不设档位。

## 6.4 最小点击热区（必须）

| 场景 | 最小热区 |
|---|---|
| 编辑器紧凑区域 | `24×24 DIP` |
| 常规按钮与独立图标 | `28×28 DIP` |
| 游戏与触控场景 | `36×36 DIP` |

- 图标本体可以小于热区；禁止通过缩小热区提高信息密度；相邻热区不得重叠误触；
- 图层状态开关热区 `26×24` 保留为组件级登记（宽 26 因行内布局既定，D2 登记组件 Token）。

## 7.1 面板与窗口阈值（必须）

| 项目 | 合同 |
|---|---|
| 应用最小窗口 | `1024×640 DIP` |
| 推荐初始窗口 | `1360×820 DIP`（不得超过当前工作区可用范围） |
| 左侧层级树最小宽度 | `220 DIP` |

| 属性表单纵向切换阈值 | 内容宽度 `< 360 DIP` |

## 7.3 现状迁移目标

- 窗口 `1400×820` → `1360×820`；`MinWidth 1100 / MinHeight 720` → `1024×640`（审计矩阵 W15/W16）；
- 左列 `MinWidth 200` → `220`；右列 `MinWidth 260` → `300`（W19/W20）；
- 日志折叠态 `MinHeight 32` 保留（折叠态），展开态由自适应逻辑约束在 `120~420`（W21 登记）。

# 8. 图标

## 8.1 图标合同（必须）

- 标准图标视口：`16×16 DIP`；工具栏或独立操作图标：`20×20 DIP`；
- 线性图标标准笔画：`1.5 DIP`（现状 `1.6/2.2` 统一迁移至 1.5）；
- 图标必须进行视觉中心校正，不能只依赖几何中心；
- 同一组图标统一端点、转角、笔画和留白；
- 禁止 Emoji、Unicode 和系统字体符号充当正式图标；
- 普通功能以线性图标为主；锁定、显示、隐藏、警告、错误、选中等状态允许局部填充或形态变化；
- 状态不能只靠颜色（形态 + 颜色双表达）；
- 无文字图标按钮必须提供 Tooltip（第 10 节）；
- 图标本体可以小于热区，热区不得缩小。

## 8.2 图标来源

- 编辑器、调试工具、控制台与启动器图标**必须**来自 `Icons/EditorIcons.axaml` 单一来源，禁止混用多来源多风格；
- 正式游戏图标允许独立艺术风格（第 16 节），但不得反向影响编辑器图标规范。

---

# 9. 边框、阴影与焦点

## 9.1 边框（必须）

- 普通边框 `1 DIP`，使用 `Color.Border.Default`；强分隔与可调整边界使用 `Color.Border.Strong`；
- 拖拽插入线 `2 DIP`（图层拖动插入线色 `#7FA8C6` 登记为组件 Token）。

## 9.2 阴影（必须）

- 普通面板、按钮和列表项**不得使用阴影**（现状 `Border.panel` 的 `0 14 30 #160f172a` 必须删除）；
- 阴影只用于真正悬浮的弹窗、菜单、Tooltip 和浮动工具条；
- 悬浮层阴影首版统一：垂直偏移 `4 DIP`、模糊 `12 DIP`、低透明黑色约 `14%`（`#24000000`）；
- **Popup 系统阴影**：Avalonia 标准 Popup/ContextMenu/Menu 自带系统阴影，使用标准控件时不得再叠加自定义阴影；只有自绘浮动层才施加统一阴影参数；同一元素禁止双重阴影；
- 阴影不得代替边框、焦点或选中反馈。

## 9.3 焦点与选中态（必须）

五种状态不得混用：

| 状态 | 视觉 | Token |
|---|---|---|
| 悬停 | 浅背景 | `Color.Hover.Bg` |
| 鼠标选中 | 浅背景 | `Color.Selection.Bg` |
| 键盘焦点 | 焦点框 | `Color.Focus` + 焦点框参数 |
| 按下 | 加深背景（组件内定义） | 组件 Token |
| 禁用 | 降低不透明度 + 禁用文字 | `Color.Text.Disabled` |

- 键盘焦点框：`2 DIP`，外偏移 `1 DIP`，使用 `Color.Focus`；焦点框不得被裁切（控件布局预留偏移空间）；
- 焦点与选中同时出现时：选中浅背景在内，焦点框在外圈，两者并存不互斥、不混色；
- 焦点不得与选中共用同一种视觉（键盘用户必须能区分「键盘位置」与「鼠标选中」）。

---

# 10. 页签、菜单、Tooltip 与弹窗

## 10.1 顶层页签强制合同（必须，15 条）

检查器、地图编辑器、偏好、模式、调试等同级页签：

1. 始终保持单行，禁止换到第二行；
2. 宽度不足时横向滚动；
3. 鼠标位于页签栏时，滚轮控制横向滚动；
4. 显示左右滚动箭头；
5. 隐藏方向显示轻微渐隐；
6. 当前页签自动滚动到完整可见；
7. 首次溢出时显示一次性提示，文案固定为：`滚动鼠标滚轮或点击箭头查看更多页签。`
8. 提供「全部页签」入口，允许直接跳转任意页签；
9. 鼠标离开页签栏后，滚轮恢复控制内容区；
10. 核心页签不可关闭；
11. 辅助页签允许关闭，已关闭页签可从「全部页签」恢复；
12. 至少始终保留一个可见页签；
13. 普通模式禁止直接拖动页签；
14. 进入「管理页签」模式后才能调整顺序；
15. 自定义顺序与关闭状态写入用户偏好，不写入项目资产；支持一键恢复默认顺序。

## 10.2 页签字号（必须）

- 顶层页签 `Font.Body=13 DIP`；二级页签（地图编辑器内「地图/图层/环境」等）`Font.Section=14 DIP`；
- 核心页签使用「图标 + 文字」；辅助页签默认文字；空间不足允许仅图标紧凑模式并必须提供完整名称 Tooltip；
- 禁止 Emoji、Unicode 或系统字体符号作为页签图标。

## 10.3 菜单（必须）

- 顶层菜单默认顺序：`文件 → 编辑 → 视图 → 地图 → 工具 → 窗口 → 帮助`；
- **只在当前已有功能存在时显示对应菜单**，不得为了凑齐结构添加空入口；
- 菜单项高度 `32 DIP`；
- 右键菜单只放与当前对象直接相关的操作；危险操作与普通操作分组；菜单顺序统一；图标尺寸统一；快捷键显示方式统一；
- 同一功能在顶部菜单、右键菜单、按钮、Tooltip、快捷键登记、日志、帮助文档中的名称必须一致。

## 10.4 Tooltip（必须）

- 无文字图标按钮必须有 Tooltip，说明「做什么」，必要时附快捷键；
- 文字已足够明确的按钮可以不重复提示；
- 禁止把长篇帮助文档塞入 Tooltip；
- 禁用控件应能说明不可用原因（Tooltip 或文案）。

## 10.5 弹窗（必须）

- 底部右对齐按钮顺序：`取消 → 次要操作 → 主要操作`；
- 危险操作：`取消 → 危险操作`；
- 危险按钮不得获得默认焦点；`Esc` 必须取消；`Enter` 只执行安全的主要操作；
- 弹窗说明操作对象、影响范围、不可逆后果、恢复方式、取消方式；
- 弹窗打开后焦点限制在弹窗内部；关闭后焦点返回原操作位置；
- 禁止弹窗嵌套弹窗；禁止普通成功操作弹窗；禁止用弹窗代替字段级错误提示；
- 极高风险操作可要求输入对象名称二次确认；高风险操作不得提供「本次会话不再提示」。

# 11. 表单和错误反馈

## 11.1 分阶段校验（必须）

| 阶段 | 检查内容 |
|---|---|
| 输入过程中 | 只检查格式、明显非法字符、明显越界值、无法继续输入的结构错误 |
| 失去焦点 | 完整字段校验：数值范围、字段格式、必填条件、单字段业务规则 |
| 提交时 | 字段间关系、业务规则、对象状态、跨字段依赖、最终完整性 |

- 不得因用户尚未输入完整内容而频繁显示错误。

## 11.2 错误呈现（必须）

- 错误显示在字段附近；页面顶部提供问题汇总；自动定位第一个错误；
- 用户输入内容不得因校验失败丢失；
- 不使用弹窗逐项提示普通字段错误；
- 错误状态不得只靠颜色（结合图标、文字、边框）。

# 12. 树、列表、图层和拖拽

## 12.1 树与列表（必须）

- 树行、列表行 `28 DIP`；图层行 `32 DIP`；
- 行内操作默认收起，悬停或选中时显示；不得因显示操作按钮导致行内容跳动；
- 长文本默认省略，提供 Tooltip、详情面板或展开查看；不允许无限撑宽面板；
- 大数据量必须虚拟化，禁止一次性创建大量 UI 元素。

## 12.2 系统与用户对象（必须）

- 系统图层与用户图层同时使用：不同语义颜色（`Color.Object.System` / `Color.Object.User`）+ 明确类型标签（「系统」「区域」文字）+ 可辨识图标或形态，**不依赖颜色即可区分**；
- 锁定、未锁定、显示、隐藏必须形态不同（图标形态 + 颜色双表达）；
- 选中行使用浅色背景（`Color.Selection.Bg`），状态图标保持足够对比（锁/眼睛图标深色可辨识，不得在深色实心框中降低可见度）。

- 插入线为 2 DIP，必须在普通、选中和悬停背景上保持清晰。

## 12.3 图层拖动（必须，事务式）

1. 操作开始时保存原状态；
2. 操作过程中只更新预览（插入线 2 DIP 提示目标位）；
3. 松手或确认后一次性提交；
4. `Esc` 取消并恢复原状态；
5. 一次拖拽只生成一个 Undo 历史节点；
6. 无实际变化时不写历史、不标记 Dirty；
7. 失败操作不得污染历史；
8. 拖动过程不写逐帧日志；
9. 非法目标明确拒绝，必要时说明拒绝原因。

# 13. 日志、通知、加载、空状态和进度

## 13.1 日志与通知优先级（必须）

```text
错误 / 警告 → 用户刚完成的操作 → 编辑器状态 → Render / Vulkan 等技术日志
```

- 技术日志完整保留，但不得覆盖用户操作通知；
- 新日志只有在用户位于底部时自动跟随；用户离开底部后暂停自动跟随；回到底部恢复跟随；
- 批量操作必须显示作用对象和数量；
- 连续拖动、PointerMoved、Hover、DragPreview、RenderFrame 不刷屏；
- 日志行高 `28 DIP`；日志列宽为组件 Token（`4/72/56/72/92/*/82`，登记）。

## 13.2 空状态（必须）

区分：初次进入、当前无数据、筛选无结果、权限不足、加载失败、数据被删除或失效。空状态必须说明「为什么为空」；有明确下一步时只提供一个主要操作入口。

## 13.3 加载与进度（必须）

- 短暂任务避免立即显示转圈，防止闪烁；
- 可计算任务显示真实进度（百分比、已完成量、总量、当前阶段），禁止伪造进度；
- 不可计算任务显示不确定进度并说明正在执行什么，不显示虚假百分比；
- 长任务必须提供：当前阶段、已完成量、取消入口、失败原因、重试或恢复方式；取消后不得留下半完成数据；后台任务不得无必要阻塞整个编辑器。

# 14. 键盘、可访问性和减少动画

## 14.1 键盘（必须）

- 所有常用功能必须可以通过键盘完成；
- `Tab / Shift+Tab` 顺序符合视觉阅读顺序；焦点不得跳入不可见、禁用或装饰性元素；
- `Enter` 执行主要操作；`Esc` 取消、关闭或退出临时状态；
- 输入框编辑时屏蔽冲突的全局快捷键；
- 快捷键集中登记；模块不得自行抢占；冲突必须在开发前解决；菜单、Tooltip 和文档中的快捷键名称必须一致。

## 14.2 可访问性（必须）

- 颜色不能作为唯一状态信息（结合图标、文字、形态、边框、位置）；
- 所有交互控件必须具备可识别名称（AutomationProperties.Name）；
- 支持系统「减少动画」设置；
- 屏幕阅读器基础结构必须建立；高级支持分阶段完善，未完成项必须登记明确待办，不得无限期推迟。

# 15. DPI 与性能

## 15.1 DPI 与分辨率验收（必须）

- DPI 至少覆盖 100% / 125% / 150% / 200%，禁止物理像素手工补偿；
- 分辨率与窗口至少覆盖 1080p、2K、4K（条件或等效缩放验证）、初始非最大化窗口、最大化窗口、面板最小宽度、高 DPI 下的窄窗口；
- 文本放大后不得遮挡、重叠、截断关键内容、破坏主要操作入口、导致控件不可点击。

## 15.2 性能门禁（必须）

- 大列表滚动不得明显卡顿；日志追加不得引发频繁 UI 重排；后台渲染更新不得阻塞 UI；
- 动效不得阻塞输入、业务或渲染线程；性能与动效冲突时优先保证响应速度。

## 15.3 动效（必须）

| 场景 | 时长 |
|---|---|
| 悬停、选中 | `80～120 ms`（默认 Token `Motion.HoverMs = 100`） |
| 展开、折叠 | `120～160 ms`（默认 Token `Motion.ExpandMs = 140`） |

- `Motion.HoverMs = 100`、`Motion.ExpandMs = 140` 为规范区间内的**全局默认 Token**（D2-F2 用户正式裁决冻结）；
- 专业组件如需使用区间内其他时长，必须走受控组件 Token 或受控例外，不得在页面直接写数字；

- 拖动、缩放、面板调整、视口交互、滚动、Gizmo 操作必须直接跟手，不得加入迟滞动画；
- 动效只用于解释状态变化，不用于装饰；
- 禁止：弹跳、强发光、长缓动、大面积渐变动画、装饰性循环动画、影响操作判断的延迟动画。

# 16. 编辑器和游戏 UI 的约束边界

## 16.1 编辑器与工具（强约束）

编辑器、调试工具、开发者控制台和启动器 UI 受本规范全部章节强约束：高信息密度、清晰、稳定、克制。

## 16.2 正式游戏 UI：基础能力强约束（必须）

游戏 UI 必须遵守：点击热区；键盘与焦点；输入校验；状态不能只靠颜色；高 DPI 与分辨率适配；错误、加载和进度反馈；性能与响应速度；危险操作；可访问性底线；数据完整性；取消和恢复规则。

## 16.3 正式游戏 UI：艺术表现弱约束（应当）

游戏 UI 可以独立决定：美术风格、品牌字体、图标表现、颜色主题、面板造型、动效风格、信息布局、军事符号、世界观表达。

- **弱约束不代表完全自由**：任何偏离本规范基础条款的决策仍需受控例外（第 20 节）；
- 游戏艺术规则不得反向污染编辑器工具规范；
- 游戏专项规则不得降低基础可用性门禁。

---

# 17. Token 层级与命名规则

## 17.1 三级 Token（必须）

| 层级 | 定义 | 示例 |
|---|---|---|
| 基础 Token | 原始数值（字号、行高、间距、控件高度、宽度等级、圆角、图标尺寸、热区、基础颜色、边框、阴影、动效时间） | `Font.Body`、`Space.8`、`Radius.Standard` |
| 语义 Token | 表达用途（文字、背景、状态、对象） | `Color.Text.Primary`、`Color.Selection.Bg` |
| 组件 Token | 只为重复使用、结构稳定的组件建立 | `Log.Accent.Error`、`DocStatus.WarningBg`、`Tab.Header.Padding`、`LayerRow.SwitchSize` |

- 页面优先引用语义 Token 与组件 Token，不直接引用基础颜色值；
- 禁止为单个页面、单个按钮或临时视觉问题创建专用 Token。

## 17.2 命名规则（必须）

- 前缀按域：`Font.`、`Color.`、`Space.`、`Size.`、`Radius.`、`Control.`、`Icon.`、`Motion.`、`Log.`、`DocStatus.`、`Layer.`、`Tab.`；
- Token 名全英文 PascalCase 分段；色值只存在于 Token 定义处；
- 同一概念全仓只允许一个 Token（禁止同值异名、同名异值）。

## 17.3 修改权限（必须）

- 页面开发者只能引用 Token，不能擅自修改全局参数；
- Token 修改必须：① 提交修改理由 → ② 说明影响范围 → ③ 检查全部引用位置 → ④ 完成全量 UI 回归验证 → ⑤ 更新本规范 → ⑥ 经过规范变更审查（第 21 节）；
- 不得为了修复一个页面直接修改全局 Token。

## 17.4 主题策略（必须）

- 当前只实现浅色主题；Token 架构必须支持未来换肤（语义 Token 映射替换）；
- 页面不得写死主题颜色；未来主题通过替换语义 Token 映射实现，不得为新增主题重写页面结构。

# 18. 自动化检查矩阵

| 类别 | 自动化检查（D2 建立） | 真机验收 |
|---|---|---|
| 字号 | 禁止未登记字号 | 实际可读性、密度 |
| 颜色 | 禁止未登记 UI 色值（扫 Editor.UI 的 .axaml/.cs 控件着色） | 对比度、状态辨识 |
| 背景 | 不超过四级结构背景 | 层级是否清晰 |
| 控件高度 | 只允许 24/28/32 及登记组件值 | 点击与视觉密度 |
| 点击热区 | 下限合同 | 误触与可点击性 |
| 圆角 | 只允许 3/6/10 及登记组件值 | 是否过度圆润 |
| 图标 | 禁止 Emoji/Unicode；尺寸、笔画、来源合同 | 笔画、对齐、状态清晰度 |
| 滚动 | 页签和主滚动区结构测试 | 滚轮方向、穿透、提示 |
| 页签 | 单行、恢复入口、当前项可见 | 实际溢出与发现性 |
| 表单 | 切换阈值、错误状态、输入保留 | 宽窄布局和输入体验 |
| 拖拽 | Preview/Commit/Cancel/Undo/Dirty | 插入线、反馈、手感 |
| 日志 | 优先级、过滤和自动跟随状态 | 是否抢位置、是否显示完整 |
| 键盘 | 焦点顺序与快捷键合同 | 实际键盘完成操作 |
| DPI | 布局尺寸测试 | 100%～200% 真机 |
| 性能 | 虚拟化和重排检测 | 滚动、追加、缩放手感 |
| 门禁 | 0W0E、测试、Git 状态 | 最终视觉裁决 |

- 自动化检查能真实拦截至少一组故意构造的违规样例，才允许接入正式门禁；
- 自动检查通过不等于视觉验收通过。

# 19. 允许清单

## 19.1 允许清单格式（必须）

| 字段 | 说明 |
|---|---|
| 类别 | 渲染色 / 数据可视化 / 领域色 / 组件例外 / 装饰例外 |
| 路径或模式 | 具体文件或代码模式 |
| 允许值 | 色值或数值范围 |
| 原因 | 为什么不受常规 UI 检查 |
| 审批 | 审批人、审批日期 |
| 有效期 | 截止日期或「长期」 |

## 19.2 预置允许类别（D1 冻结）

| 类别 | 内容 | 说明 |
|---|---|---|
| 渲染器颜色 | Shader 参数、ClearColor、Vulkan 管线常量 | 属于渲染层，不属于 Avalonia UI 控件着色 |
| 渲染内容色 | 天空、地表、网格、坐标轴、Gizmo、世界原点等程序化绘制色（如 F2A 冻结网格配色、NavGizmo 配色） | 屏幕空间绘制色，按各自渲染合同冻结 |
| 数据可视化内容色 | 未来游戏数据可视化、图表系列色 | 需登记；日志级别色已归 `Log.Accent.*` 组件 Token |
| 领域对象色 | `Color.Object.System` / `Color.Object.User` 及层类型标签色（区域 `#E8F3F6/#326B7B/#B9D7DE`、系统 `#F0F2F4/#687582/#D5DBE0`） | 已 Token 化或登记组件 Token |
| 组件例外 | 日志行级别圆点（圆角=半径）、拖动插入线（圆角 1）、图层状态开关热区 `26×24`、树引导线 `#C7D7EA`、等宽字体（日志/数值列） | 结构稳定组件，D2 建组件 Token |
| 受控例外 | 按第 20 节申请并登记 | 每项含有效期与复查方式 |

## 19.3 边界规则（必须）

- 任何出现在 `XuanYu.Editor.UI` 的 .axaml/.cs 中、用于 **Avalonia UI 控件着色**的颜色，必须属于语义 Token、组件 Token 或允许清单；
- 出现在 shader、渲染管线、像素数据中的颜色，属于渲染允许类别，不受 UI 色值检查；
- 允许清单由用户审批，D2 起由自动化检查引用。

# 20. 受控例外

## 20.1 例外申请（必须）

例外必须同时满足：

1. 指出偏离的具体条款；
2. 说明通用规则无法满足的原因；
3. 明确影响模块、界面和边界；
4. 提供替代规则，不能留下无标准区域；
5. 经过 UI 规范审查（用户审批）；
6. 建立专项自动化验证；
7. 完成专项真机验收；
8. 正式登记（写入允许清单或债务登记），不得口头放行。

## 20.2 例外管理（必须）

- 页面开发者不能自行宣布例外；
- 例外必须包含期限与复查方式；到期未复查的例外自动失效；
- 不得以「实现方便」「已有代码如此」「与本轮无关」作为例外理由。

# 21. 规范变更流程

## 21.1 变更触发（必须）

以下情况必须走独立治理轮，**不得在普通功能轮顺手修改 Token 或本规范**：

- 需要新增字号、颜色、间距或尺寸等级；
- 需要修改已冻结 Token 数值；
- 需要修改本规范条款；
- 自动化门禁与真实视觉效果矛盾。

## 21.2 变更八步（必须）

1. 说明原因；2. 说明受影响组件；3. 更新本规范；4. 更新 Token；5. 更新测试；6. 执行全量 UI 回归；7. 完成真机复验；8. 保留变更记录（写入本规范第 23 节变更历史）。

# 22. 真机验收要求

## 22.1 原则（必须）

- 自动化通过不能替代真机验收；自动检查通过不等于视觉验收通过；
- 验收清单必须使用中文 IPO 格式：序号、路径（UI 真实中文名）、输入 I、过程 P、输出 O；输出必须可由画面、状态、日志、数据明确判定；
- 「最大化正常 ≠ 通过」，初始非最大化窗口（推荐 1360×820）是主验收尺寸；
- 每轮整改必须覆盖：100%/125%/150%/200% DPI、初始非最大化/最大化/恢复/最小窗口/连续拖动、1080p（2K/4K 条件或等效缩放）、面板最小宽度与高 DPI 窄窗口。

## 22.2 验收清单

`docs/ui/玄域引擎_UI真机基线清单.md` 为共用验收清单（20 组 IPO），A1 全量执行；D3~D6 按轮次抽组执行。
