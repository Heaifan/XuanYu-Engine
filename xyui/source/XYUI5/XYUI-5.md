- 5.01 · Stack / 堆叠布局
    - Ownership Check
        - Existing Upstream Rule
            - XYUI-0
                - 拥有 Spacing Token
                - 拥有 Density
                - 拥有 DIP 单位规则
                - 拥有基础 Alignment / Layout 原则
                - 未拥有独立 Stack Layout Component
            - XYUI-1
                - 无 Stack 所有权
            - XYUI-2
                - 无 Stack 所有权
            - XYUI-3
                - 无 Stack 所有权
            - XYUI-4
                - 无 Stack Layout 所有权
        - This Item Inherits
            - XYUI-0 Spacing Token
            - XYUI-0 Density
            - XYUI-0 DIP
            - XYUI-0 Accessibility
            - XYUI-0 Layout 基础原则
        - This Item Owns
            - 单轴排列
            - Direction
            - Gap 消费方式
            - Cross-Axis Alignment
            - Main-Axis Distribution
            - Child Auto / Fill
        - This Item Must Not Redefine
            - Spacing Token 数值
            - Density Token
            - 颜色
            - Surface
            - Border
            - Shadow
            - Focus
            - 交互状态
            - 响应式 Breakpoint
        - Result
            - NEW + EXTENSION
            - 允许正式进入 XYUI-5
    - 用途
        - 沿单一轴线连续排列一组 Child
        - 作为 XYUI 最基础的一维布局机制
        - 适用于 Vertical Content Flow
        - 适用于 Horizontal Action Flow
        - 适用于 Inspector 内部线性内容
        - 适用于表单
        - 适用于 Dialog
        - 适用于 Toolbar 内部基础排列
        - 适用于 Header
        - 适用于局部内容组合
    - 最终方案
        - Pure Axis Stack
        - Semantic Gap Stack
        - Distribution Stack
        - 采用方案1+2+3
        - 不采用 Adaptive Orientation 作为 Stack 自身职责
    - 核心原则
        - Stack 只负责一维布局
        - Stack 本身不可见
        - Stack 不拥有视觉容器身份
        - Stack 不负责二维轨道
        - Stack 不负责自动换行
        - Stack 不负责滚动
        - Stack 不负责响应式 Breakpoint
        - Stack 不负责视觉分组
        - Stack 不建立独立 Spacing Token
        - Stack Gap 必须消费 XYUI-0 Foundation Spacing
        - Stack 不扩展成完整 Flexbox
    - 基础结构
        - Stack
            - Children
    - Direction
        - Vertical
            - Child 沿垂直主轴连续排列
        - Horizontal
            - Child 沿水平主轴连续排列
        - 原则
            - Direction 必须显式或由组件 Variant 明确决定
            - Stack 不根据当前宽度自行猜测 Direction
    - Vertical Stack
        - 适用
            - Inspector Property Group
            - Settings
            - Dialog Content
            - Form
            - Section Content
            - Message List
        - Main Axis
            - Vertical
        - Cross Axis
            - Horizontal
    - Horizontal Stack
        - 适用
            - Action Group
            - Header
            - Toolbar Group
            - Label + Value
            - Inline Status
        - Main Axis
            - Horizontal
        - Cross Axis
            - Vertical
    - Gap
        - 用途
            - 控制相邻 Child 之间的标准距离
        - 来源
            - 必须引用 XYUI-0 Spacing Token
        - 允许语义级别
            - None
            - XS
            - S
            - M
            - L
            - XL
        - 注意
            - 本项不重新定义这些 Token 的具体 DIP 数值
            - 具体值由 XYUI-0 Canonical Foundation 提供
        - 原则
            - 兄弟 Child 间距优先由 Stack Gap 统一控制
            - 避免 Child 自己携带重复 Margin
    - Gap 场景建议
        - Compact Tool Flow
            - 优先较小 Foundation Spacing
        - Standard Editor Flow
            - 优先标准 Foundation Spacing
        - Loose Content Group
            - 优先较大 Foundation Spacing
        - 具体映射
            - 由上层组件与 Density Context 决定
            - 不得在 Stack 内重新定义 Density → Gap 自动表
    - Alignment
        - 定义
            - 控制 Child 在 Cross Axis 上的位置
        - Start
        - Center
        - End
        - Stretch
        - 原则
            - 输入型内容通常允许 Stretch
            - 固有尺寸图标与按钮通常保持 Auto
            - 不得为了视觉居中破坏内容语义对齐
    - Main-Axis Distribution
        - Start
            - 从主轴起点连续排列
        - Center
            - 整体居中
        - End
            - 整体靠主轴末端
        - SpaceBetween
            - 将剩余空间放在 Child 之间
        - 默认
            - Start
        - 原则
            - 只保留高频且明确的 Distribution
            - 不继续增加 SpaceAround
            - 不继续增加 SpaceEvenly
            - 不建立复杂 Flex Distribution
    - Start
        - 适用
            - 绝大多数内容布局
        - 特点
            - 稳定
            - 可预测
    - Center
        - 适用
            - 明确居中的紧凑内容
        - 禁止
            - 因为容器很宽就随意居中普通表单
    - End
        - 适用
            - 右侧操作
            - 末端状态
        - 禁止
            - 用 End 解决本应由 Fill 解决的结构关系
    - SpaceBetween
        - 适用
            - Title + Actions
            - Primary Area + Secondary Area
        - 原则
            - 只有存在明确“两端关系”时使用
        - 禁止
            - 普通按钮组为了铺满整行使用 SpaceBetween
    - Child SizeMode
        - Auto
            - 由 Child 固有尺寸与自身约束决定
        - Fill
            - 承担父 Stack 剩余主轴空间
        - 原则
            - 默认 Auto
            - Fill 必须显式
            - 不得所有 Child 默认平均 Fill
    - Auto Child
        - 适用
            - Button
            - Icon
            - Label
            - Status
            - Action
        - 行为
            - 只占所需空间
    - Fill Child
        - 适用
            - Header Title Area
            - Main Content Area
            - Field
            - 需要承担剩余空间的区域
        - 行为
            - 获取主轴剩余空间
        - 原则
            - 明确谁承担剩余空间
    - 多个 Fill
        - 允许
            - 仅在规则明确的简单场景
        - 不建议
            - 复杂比例分配
        - 禁止
            - 在 Stack 中继续引入完整 FlexGrow 权重系统
        - 复杂比例
            - 交由 Grid / SplitPane 等更合适布局机制
    - Stack + Margin
        - Stack Gap
            - 兄弟元素之间的标准距离
        - Child Margin
            - 只允许特殊局部偏移
        - 禁止
            - Gap 与相同方向 Margin 重复叠加
            - 大量使用 Margin 修补布局
    - Stack + Padding
        - Stack
            - 默认不拥有视觉容器 Padding
        - Padding
            - 由实际父级容器或 Composition Context 提供
        - 原因
            - 避免 Stack 同时承担布局与视觉容器职责
    - Stack + Surface
        - Surface
            - 属于 Foundation / 对应容器层
        - Stack
            - 仅负责其中的排列
        - 结构示例
            - Surface
                - Stack
    - Stack + Panel
        - Panel
            - 由已有上位规范负责身份与结构
        - Stack
            - 只负责 Panel 内部线性排列
        - 不得
            - 让 Stack 重新定义 Panel Padding / Header / Border
    - Stack + Grid
        - Stack
            - 一维关系
        - Grid
            - 二维轨道关系
        - 原则
            - 具有跨行列对齐需求时使用 Grid
            - 不要连续嵌套大量 Horizontal Stack 模拟 Grid
    - Stack + Wrap
        - Stack
            - 不换行
        - Wrap
            - 空间不足自动流式换行
        - 禁止
            - Horizontal Stack 偷偷变 Wrap
    - Stack + Scroll
        - Stack
            - 只负责内容排列
        - ScrollArea
            - 负责 Overflow 与 Scroll
        - 组合
            - ScrollArea
                - Stack
    - Stack + Spacer
        - 优先
            - Fill
            - SpaceBetween
        - Spacer
            - 只负责明确的固定或弹性间隔需求
        - 禁止
            - 大量 Spacer 作为布局补丁
    - 嵌套
        - 允许
            - Vertical Stack 内嵌 Horizontal Stack
            - Horizontal Stack 内嵌 Vertical Stack
        - 典型
            - Vertical Stack
                - Property Row
                    - Horizontal Stack
        - 原则
            - 保持嵌套语义清晰
            - 能用 Grid 明确表达时不要继续深层嵌套 Stack
    - Density
        - Stack 不定义新的 Density
        - Stack 消费上层 Density Context
        - Gap Token 的选择
            - 由组件 Variant / Composition Rule 决定
        - 禁止
            - Stack 自行监听 Density 后隐式修改大量内部布局
    - Responsive
        - Stack 自身不拥有 Breakpoint
        - Stack 自身不根据宽度自动换 Direction
        - 响应式方向切换
            - 归后续 AdaptiveLayout
        - AdaptiveLayout 可以输出
            - Direction = Horizontal
            - Direction = Vertical
        - Stack 只执行最终明确 Direction
    - 视觉规则
        - Background
            - None
        - Border
            - None
        - Shadow
            - None
        - Glow
            - None
        - CornerRadius
            - None
        - Stack 本身不可见
    - State
        - Stack 本身无
            - Hover
            - Selected
            - Active
            - Focus
            - Disabled
        - 这些状态属于 Child
    - Accessibility
        - Stack 默认不进入 Focus Flow
        - Stack 不改变 Child 的逻辑顺序
        - 视觉排列顺序应与逻辑顺序一致
        - 不得仅为视觉布局改变 Keyboard Navigation 顺序
    - UI代码
        - Stack.Direction
            - Vertical | Horizontal
        - Stack.Gap
            - XY.Spacing.*
        - Stack.Align
            - Start | Center | End | Stretch
        - Stack.Distribution
            - Start | Center | End | SpaceBetween
        - Stack.Child.SizeMode
            - Auto | Fill
        - Stack.Background
            - None
        - Stack.Border
            - None
        - Stack.Shadow
            - None
        - Stack.Wrap
            - False
        - Stack.Scroll
            - False
        - Stack.ResponsiveDirection
            - Not Owned
        - Stack.Unit
            - DIP via XYUI-0
    - 禁止事项
        - 禁止 Stack 建立自己的 Spacing Token 数值
        - 禁止 Stack 自带 Background
        - 禁止 Stack 自带 Border
        - 禁止 Stack 自带 Shadow
        - 禁止 Stack 自带 Scroll
        - 禁止 Stack 自动 Wrap
        - 禁止 Stack 自己实现 Breakpoint
        - 禁止 Stack 自动猜测 Direction
        - 禁止大量 Child Margin 替代 Gap
        - 禁止 Gap 与重复 Margin 双倍叠加
        - 禁止用多层 Stack 模拟复杂 Grid
        - 禁止把 Stack 扩展成完整 Flexbox
        - 禁止增加复杂 Grow / Shrink / Order 系统

- 5.02 · Grid / 网格布局
    - Ownership Check
        - Existing Upstream Rule
            - XYUI-0
                - 拥有 Spacing Token
                - 拥有 Alignment
                - 拥有 Density
                - 拥有 DIP
                - 拥有部分通用 Layout 原则
                - 未拥有独立通用 Grid Layout Component
            - XYUI-1
                - DataGrid 属于数据展示与编辑组件
                - 不拥有通用 Grid Layout
            - XYUI-2
                - 无 Grid Layout 所有权
            - XYUI-3
                - 无 Grid Layout 所有权
            - XYUI-4
                - Skeleton 等内容引用过 Grid / DataGrid 结构
                - 不拥有通用 Grid Layout
        - This Item Inherits
            - XYUI-0 Spacing
            - XYUI-0 Alignment
            - XYUI-0 Density
            - XYUI-0 DIP
            - XYUI-0 Accessibility
        - This Item Owns
            - 二维轨道布局
            - Rows
            - Columns
            - Row / Column Position
            - 基础 RowSpan / ColumnSpan
            - Track Sizing
                - Auto
                - Fixed
                - Fill
                - MinMax
            - Cell Alignment
        - This Item Must Not Redefine
            - DataGrid Component
            - Inspector Component
            - Spacing Token 数值
            - Breakpoint System
            - Surface
            - Border
            - Selection
            - Focus
        - Result
            - NEW
    - 用途
        - 建立二维 Row × Column 布局关系
        - 保证多个 Row 之间共享稳定 Column Alignment
        - 适用于 Inspector 属性布局
        - 适用于 Settings Form
        - 适用于参数矩阵
        - 适用于复杂工具配置区域
        - 适用于 Label + Field + Action
        - 适用于具有明确二维关系的内容
    - 最终方案
        - Explicit Track Grid
        - Semantic Track Sizing
        - 采用方案1+2
        - 基础 Span 能力随 Explicit Track Grid 保留
        - 不采用 Span-Aware Grid 作为独立强化体系
        - 不在本项定义 Responsive Breakpoint
    - 核心原则
        - Grid 负责二维轨道关系
        - Grid 自身不可见
        - Grid 不承担数据组件语义
        - Grid 不等于 DataGrid
        - Grid 不等于 Table
        - Grid 不等于 Inspector
        - 轨道关系必须可预测
        - 主要内容优先使用 Fill
        - 固有尺寸内容优先 Auto
        - 长期稳定尺寸才使用 Fixed
        - 需要上下限约束时使用 MinMax
        - 不得大量硬编码随机 Column Width
        - 不得通过大量嵌套 Stack 模拟明确二维关系
    - 基础结构
        - Grid
            - Rows
            - Row Track
        - Columns
            - Column Track
        - Children
            - Row
            - Column
            - Optional RowSpan
            - Optional ColumnSpan
    - Row
        - 表示垂直方向轨道
        - 可以使用
            - Auto
            - Fixed
            - Fill
            - MinMax
        - 默认倾向
            - 内容型 Row 使用 Auto
            - 主内容区域必要时使用 Fill
    - Column
        - 表示水平方向轨道
        - 可以使用
            - Auto
            - Fixed
            - Fill
            - MinMax
        - 典型
            - Label Column
            - Field Column
            - Action Column
    - Track Sizing
        - Auto
            - 根据该 Track 内内容的固有尺寸决定
        - Fixed
            - 使用明确尺寸
        - Fill
            - 占用可分配剩余空间
        - MinMax
            - 在最小值与最大值之间弹性变化
    - Auto
        - 适用
            - Label
            - Icon
            - Status
            - Action
            - 短内容
        - 原则
            - 只占必要空间
            - 不得无意义扩张
    - Fixed
        - 适用
            - 长期统一的标准列
            - 序号
            - 固定图标栏
            - 明确规范化 Label Column
        - 原则
            - 固定尺寸必须来自正式 Layout Rule 或 Component Rule
            - 不得每个页面随意定义不同宽度
    - Fill
        - 适用
            - 主要 Field
            - 主要 Editor
            - 主要 Content
        - 原则
            - 优先由真正需要空间的主内容承担剩余宽度
            - 不得辅助信息无脑 Fill
    - MinMax
        - 用途
            - 保证最低可用尺寸
            - 同时允许适度扩展
        - 结构
            - Min
                - 最低可用尺寸
            - Max
                - 最高合理尺寸
        - 原则
            - Min 必须保证可操作性
            - Max 用于避免内容无限拉长
            - 具体数值由使用 Grid 的组件规范决定
    - 典型二列 Grid
        - Column 1
            - Label
            - Auto 或正式 Fixed
        - Column 2
            - Field
            - Fill
        - 适用
            - Inspector
            - Settings
            - Property Editor
    - 典型三列 Grid
        - Column 1
            - Label
            - Auto 或 Fixed
        - Column 2
            - Editor
            - Fill
        - Column 3
            - Action
            - Auto
        - 示例
            - 名称
                - Text Field
                - Reset
    - Cell Position
        - Row
            - 明确 Child 位于哪个 Row
        - Column
            - 明确 Child 位于哪个 Column
        - 原则
            - 逻辑位置必须清晰
            - 不得依赖添加顺序产生不可见的复杂自动定位
    - RowSpan
        - 基础能力
        - 默认
            - 1
        - 用途
            - 少量需要跨多个 Row 的内容
        - 原则
            - 谨慎使用
            - 不是主要布局手段
    - ColumnSpan
        - 基础能力
        - 默认
            - 1
        - 用途
            - Description
            - Preview
            - Section Message
            - 需要占据完整宽度的内容
        - 原则
            - 允许少量结构性跨列
            - 不得用大量 Span 拼装自由画布
    - Span 限制
        - 基础 Span 保留
        - 不建立复杂 Span Pattern Library
        - 不鼓励深度 RowSpan
        - 不鼓励大量交叉 Span
        - 如果布局需要大量 Span 才成立
            - 重新审视是否应该拆为多个 Grid / Stack / Section
    - RowGap
        - 引用 XYUI-0 Spacing Token
        - 不在本项重新建立数值
    - ColumnGap
        - 引用 XYUI-0 Spacing Token
        - 不在本项重新建立数值
    - 允许
        - RowGap 与 ColumnGap 使用不同 Foundation Spacing Level
    - 禁止
        - Grid 建立第二套 Spacing Token
        - Child 使用大量 Margin 代替 Grid Gap
    - Cell Alignment
        - Horizontal
            - Start
            - Center
            - End
            - Stretch
        - Vertical
            - Start
            - Center
            - End
            - Stretch
        - 原则
            - Input / Field 通常允许 Stretch
            - Icon / Action 通常保持 Auto
            - 文本对齐应服从信息语义
    - Stretch
        - 用途
            - 让 Child 填充当前 Cell 可用空间
        - 注意
            - Stretch 不等于 Track Fill
        - 区别
            - Track Fill
                - 决定轨道如何占父容器空间
            - Child Stretch
                - 决定 Child 如何占当前 Cell
    - Grid + Stack
        - Grid
            - 负责二维大结构
        - Stack
            - 负责单个 Cell 内部一维排列
        - 典型
            - Grid Cell
                - Vertical Stack
                    - Title
                    - Description
        - 原则
            - 职责分层
    - Grid + DataGrid
        - Grid Layout
            - 纯布局器
        - DataGrid
            - 正式数据组件
            - 拥有 Row / Cell / Header / Selection / Sorting 等语义
        - 禁止
            - 使用通用 Grid 重新实现 DataGrid 组件规范
    - Grid + Inspector
        - Grid
            - 提供 Label / Field / Action 对齐能力
        - Inspector
            - 拥有属性编辑业务结构
        - Grid 不重新定义
            - Inspector Label Style
            - Field Style
            - Section Style
    - Grid + Surface
        - Surface
            - 负责视觉承载
        - Grid
            - 负责内部二维排列
    - Grid + Scroll
        - Grid
            - 不拥有 Scroll
        - ScrollArea
            - 负责 Overflow
        - 典型
            - ScrollArea
                - Grid
    - Grid + Wrap
        - Grid
            - 强调轨道对齐
        - Wrap
            - 强调自然流换行
        - 选择规则
            - 需要稳定列关系
                - Grid
            - 只需要顺序流动
                - Wrap
    - Grid + AdaptiveLayout
        - Grid 核心
            - 不拥有 Breakpoint
            - 不自行判断 Wide / Medium / Narrow
        - AdaptiveLayout
            - 后续负责根据空间选择 Grid Variant
        - Grid 可以被上层切换
            - Column Definition
            - Track Count
            - Span Strategy
        - 但触发条件
            - 不属于 Grid 本项
    - Density
        - Grid 不建立 Density
        - 继承上层 XYUI-0 Density Context
        - RowGap / ColumnGap
            - 使用对应 Foundation Spacing
        - 组件高度
            - 由具体组件规范决定
    - 视觉规则
        - Background
            - None
        - Border
            - None
        - Shadow
            - None
        - Glow
            - None
        - CornerRadius
            - None
        - 正式 UI 不显示 Track Guide
        - 设计调试模式可以可视化 Track
    - State
        - Grid 本体无
            - Hover
            - Selected
            - Active
            - Focus
            - Disabled
        - 状态属于 Child
    - Accessibility
        - Grid 默认不进入 Focus Flow
        - 不得为了视觉布局改变逻辑阅读顺序
        - Keyboard Navigation Order 应遵循组件语义
        - 二维视觉布局不自动等于二维键盘导航

        - Content 未超过 Viewport
            - 不需要滚动

        - Content 超过禁止轴

            - DisplayMode
            - Track
            - Thumb
            - Hover
            - Scrolling
            - AutoHide
        - 原则
            - ScrollArea 只声明滚动能力
            - Foundation 决定滚动条表现
    - Scroll Position Policy
        - Preserve
        - Reset
        - FollowEnd
        - AnchorItem
    - Preserve
        - 定义
            - 内容更新后尽可能保持当前阅读位置
        - 适用
            - Inspector
            - Tree
            - List
            - Document
            - 普通数据刷新
        - 默认建议
            - 大多数普通 ScrollArea
    - Reset
        - 定义
            - 状态变化后回到逻辑起点
        - 适用
            - 切换完全不同数据源
            - 打开新的独立内容
            - 明确重新初始化 View
        - 禁止
            - 普通 Refresh 无脑 Reset
    - FollowEnd

        - 适用
            - Console
            - Log
            - Output
            - Streaming Data

            - 用户当前仍处于末端

                - 暂停自动跟随
            - 用户重新回到底部
                - 可以重新进入 FollowEnd
        - 禁止
            - 用户正在阅读历史时强行拖回底部
    - AnchorItem
        - 定义
            - 以逻辑 Item 为位置锚点
        - 适用
            - Tree
            - Virtual List
            - Dynamic List
            - 大量 Item 插入 / 删除场景
        - 规则
            - 内容变化后尽可能保持 Anchor Item 在相近视觉位置
        - 优势

        - 优先使用

        - 其次
            - Logical Offset

    - Content Append
        - 普通 List
            - Preserve
        - Log
            - FollowEnd
        - Streaming Panel
            - 根据用户是否位于 End 决定
    - Content Insert Above
        - 如果使用 AnchorItem

        - 不得

    - Content Remove
        - Anchor 仍存在
            - 继续保持
        - Anchor 被删除
            - 选择最近合理 Neighbor Anchor

    - Resize
        - Viewport 尺寸变化
            - 尽量保持当前上下文
        - Scroll Offset 超过新 Max
            - Clamp 到合法范围
        - 不得
            - Resize 就 Reset 到 Start
    - Selection Reveal
        - 外部命令要求选中某对象
            - 允许 ScrollIntoView
        - 原则
            - 只有明确导航行为才主动改变 Scroll Position
        - 禁止
            - 普通 Selection State 更新就强行滚动
    - Focus Reveal
        - Keyboard Focus 移动到视口外 Child
            - 允许最小必要 ScrollIntoView
        - 原则
            - 只滚到足以看见 Focus Target
            - 避免每次 Focus 都强制居中
    - Nested Scroll
        - 结构
            - Parent ScrollArea
                - Child
                    - Inner ScrollArea
        - 允许
            - 只有确实存在独立滚动语义时嵌套
        - 不建议
            - 无意义多层滚动容器
    - Nested Scroll Arbitration
        - Pointer 位于 Inner ScrollArea
            - Inner 在当前方向仍可滚
                - Inner 消费
            - Inner 已达当前方向边界
                - 允许 Handoff 给 Parent
        - 原则
            - 单一主要消费者
            - 稳定边界移交
    - Scroll Handoff
        - 触发
            - Inner 已经到达对应边界
            - 用户继续同方向滚动
        - 结果
            - 后续滚动可以由 Parent 接管
        - 不得
            - 一个 Wheel Delta 同时明显移动 Inner 与 Parent
    - Wheel
        - 按照 Nested Arbitration 处理
        - 滚动方向
            - 映射到声明 Axis
    - Trackpad
        - 支持连续细粒度输入
        - Handoff 必须避免边界抖动
        - 可以使用轻度稳定阈值
        - 不得产生明显粘滞
    - Touch
        - 支持直接 Scroll Gesture
        - Nested Arbitration 与 Pointer Wheel 共享语义
        - 动量滚动
            - 不得导致多个容器同时获得惯性
    - Keyboard Scroll
        - PageUp / PageDown
        - Home / End
        - Arrow Key
        - 具体键盘行为由当前 Focus Context 决定
        - 不得
            - 无 Focus Context 时随机滚动多个区域
    - Overscroll

            - 克制
        - 禁止
            - 强烈弹性 Bounce
            - 明显娱乐化 Overscroll
        - 平台需要时

    - ScrollArea + Wrap

        - ScrollArea

    - ScrollArea + Virtualization

    - ScrollArea + Loading

    - ScrollArea + Focus

        - Child Focus 保持正常

        - Scrollbar 自动隐藏不能成为判断“这里可滚”的唯一渠道

    - State

        - Vertical Split

        - 命名原则

            - 任一 Pane 可以再次承载 SplitPane

            - SplitNode

                - Second
                    - Pane 或 SplitNode
        - 示例
            - Root Split
                - Left
                    - Hierarchy
                - Right
                    - Split
                        - Top
                            - Viewport
                        - Bottom
                            - Log

        - 不得使用大量绝对坐标模拟 Split
        - 每个 SplitNode 只负责自身二分关系
        - 父节点不得直接修改孙节点内部 Allocation
        - 递归结构必须可验证
        - 递归结构必须可序列化
    - Pane
        - 可以承载
            - Panel
            - Viewport
            - Document
            - ScrollArea
            - 其他 Layout
            - 另一个 SplitPane
        - Pane 自身

            - 不自动拥有 Border
            - 不自动拥有 Header

        - Fill
        - Ratio

            - Inspector
            - Navigation
            - Tool Pane

        - 禁止
            - 随页面随机硬编码大量不同 Fixed Size
    - Fill
        - 定义
            - 承担当前 Split 剩余空间
        - 适用
            - Viewport
            - Document
            - Main Editor
            - Main Canvas
        - 典型
            - Secondary Pane = Fixed
            - Primary Pane = Fill
    - Ratio
        - 定义
            - First / Second 根据比例分配可用空间
        - 示例
            - 0.35 / 0.65
            - 0.50 / 0.50
        - 适用
            - 双文档比较
            - 双 Viewport
            - 两个同等级工作区域
        - 原则
            - Ratio 表达空间关系
            - 不是新的百分比视觉组件
    - Size Allocation
        - 计算时必须扣除
            - Splitter 占用
            - 必要 Container Padding
        - 然后再分配给
            - First Pane
            - Second Pane
    - Fixed + Fill
        - 典型专业编辑器模式
        - 辅助 Pane
            - Fixed
        - 主 Pane
            - Fill
        - Resize 后
            - Fixed Pane 可以根据用户拖动更新目标 Size
            - Fill Pane 继续承担剩余空间
    - Ratio + Ratio
        - 两个 Pane 同等级时使用

            - 归一化为有效比例

            - 更新 Ratio

            - 保持比例关系

        - 第三步

- 5.07 · OverlayLayout / 叠层布局

                - 不拥有 Overlay Layout
            - XYUI-2
                - 无 Overlay Layout 所有权
            - XYUI-3
                - Menu / Popup 等组件可能使用 Overlay Host
                - 不拥有通用 Overlay Layout
            - XYUI-4
                - SelectionOutline
                - BoundingBox
                - DragFeedback
                - DropIndicator
                - Marquee
                - Lasso
                - 均可能作为 Overlay Child
                - 但不拥有 Layer Composition
        - This Item Inherits
            - XYUI-0 Alignment
            - XYUI-0 Spacing
            - XYUI-0 HitTarget
            - XYUI-0 Focus
            - XYUI-0 Input Contract
            - XYUI-0 DIP
            - XYUI-4 Feedback Components
        - This Item Owns
            - Layer Composition
            - Z Order
            - Overlay Placement
            - Hit-Test Routing
            - Semantic Overlay Planes
        - This Item Must Not Redefine
            - Tooltip
            - Menu
            - Popup
            - Dialog
            - SelectionOutline
            - BoundingBox
            - DragFeedback
            - DropIndicator
            - Focus Visual
            - Modal Visual
        - Result
            - NEW + COMPOSITION
    - 用途
        - 在同一 Layout Region 中叠加多个视觉与交互层
        - 支持 Viewport Overlay
        - 支持 Canvas Overlay
        - 支持地图编辑反馈
        - 支持 Selection Overlay
        - 支持 Gizmo / Handle
        - 支持 Drag / Drop Feedback
        - 支持 HUD
        - 支持临时状态层
        - 避免依赖任意绝对 Z-Index
    - 最终方案
        - Layer Stack Overlay
        - Aligned Overlay Slots
        - Hit-Test Aware Overlay
        - Semantic Overlay Planes
        - 方案1+2+3+4全部采用
    - 核心原则
        - OverlayLayout 负责叠层关系
        - OverlayLayout 不负责 Child 自身视觉
        - 视觉层级与输入层级必须分离
        - Z Order 高不等于一定拦截 Pointer
        - Overlay Child 应优先使用语义 Placement
        - 禁止普通业务组件任意争抢超大 Z-Index
        - Overlay 不得无意义改变 Base Layout 尺寸
        - Overlay 出现和消失默认不引起 Base Layout Reflow

            - 主要内容
            - Overlay Children

            - Scene

            - 正常参与 Scroll Flow
        - Approaching
            - 逐渐接近 Sticky Edge
        - Stuck
            - 到达 Edge 后保持位置
        - PushOff
            - 下一同级 Sticky 到来
            - 当前 Sticky 被推出
        - Released
            - 离开自身 Scope
    - Sticky Edge
        - Top
            - Core 推荐
        - Bottom
            - 允许特殊场景
        - 默认
            - Top
    - Top Sticky
        - Child 未到达顶部
            - 正常滚动
        - Child 到达顶部
            - 保持在 Viewport Top
        - 直到
            - 下一同级 Sticky Push-Off
            - 自身 Scope 结束
    - Bottom Sticky
        - 允许
            - 确有底部持续上下文需求的场景
        - 不建议
            - 普通 Inspector / List 默认使用
    - Push-Off
        - 当前 Sticky
            - 保持在 Edge
        - 下一同级 Sticky 接近
            - 逐渐占用当前 Sticky 所需空间
        - 当前 Sticky
            - 被自然推出 Viewport
        - 下一 Sticky
            - 接管 Sticky Edge
        - 原则
            - 两个同级 Header 不叠在一起
            - 切换必须连续
    - Sticky Scope
        - 每个 Sticky Region 必须属于明确逻辑 Scope
        - 示例
            - Geometry Section
                - Geometry Header
                - Geometry Content
                - Geometry Boundary
        - Sticky Header
            - 只能在该 Scope 有效
    - Release Boundary
        - 到达 Scope End
            - 当前 Sticky 必须释放
        - 不得
            - Geometry Header 继续粘在 Render Section 上方
    - Same-Level Rule
        - Push-Off 默认发生在同级 Sticky 之间
        - 例如
            - Geometry
            - Render
            - Physics
        - 它们互相替换
    - Multi-Level Sticky
        - Core
            - 不提供自动多层 Stack
        - 原因
            - 复杂度高
            - 容易占据过多 Viewport
            - 大多数 Inspector 只需要一个当前 Section Header
        - 未来扩展
            - 只有 Toolbar + Section + Subsection 确有同时 Sticky 需求时加入
    - Sticky + Fixed Header
        - 允许同时存在
        - 结构
            - Panel
                - Fixed Header
                - ScrollArea
                    - Sticky Section Header
                    - Content
        - Sticky Edge
            - 相对于 Scroll Viewport
            - 而不是覆盖 Panel Fixed Header
    - Sticky + ScrollArea
        - ScrollArea
            - 负责滚动
        - StickyRegion
            - 监听自己相对 Viewport 的位置
            - 决定 Normal / Stuck / Released
        - 不得
            - Sticky 自己修改 Scroll Offset
    - Sticky + Section
        - Section
            - 负责标题和内容结构
        - StickyRegion
            - 只给 Section Header 增加滚动吸附行为
        - 不得
            - 创建 StickySection 第二套 Section Component
    - Sticky + DataGrid
        - Column Header 永久固定
            - 更接近 Fixed Header
        - Group Header 随滚动吸顶
            - 适合 StickyRegion
        - 二者应明确区分
    - Sticky + Excel 类比
        - Excel Freeze Row
            - 通常从一开始固定指定 Row
        - StickyRegion
            - 根据 Scroll Position 动态决定当前吸附对象
        - 共同点
            - 滚动时保持重要上下文可见
    - Resize
        - Viewport Resize
            - 重新计算 Sticky Boundary
        - 不得
            - 改变逻辑 Scope
            - 改变 Scroll Position
    - Content Update
        - 当前 Sticky Item 仍存在
            - 保持 Sticky Identity
        - 当前 Sticky Item 被删除
            - 选择当前 Scroll Position 下新的合法 Sticky
        - 不得
            - 因为数据刷新闪回第一个 Section
    - Focus
        - Sticky 激活不得抢夺 Focus
        - Sticky Header 内原本存在交互控件
            - 保持其正式 Focus 语义
    - Selection
        - Sticky 状态变化不修改 Selection
    - Accessibility
        - Sticky Header 在 Accessibility Tree 中仍保持同一逻辑节点
        - 不得因为 Normal → Stuck 创建重复可访问节点
        - Screen Reader 顺序保持内容逻辑顺序
    - 视觉规则
        - StickyRegion 本身不拥有 Background
        - StickyRegion 本身不拥有 Border
        - Section Header Visual
            - 继续引用正式 Section/Header 规范
        - 必要的层级显示
            - 消费现有 Surface / Border Token
            - 不得建立 Sticky 专属视觉语言
    - UI代码
        - StickyRegion.Edge
            - Top | Bottom
        - StickyRegion.Mode
            - Normal | Stuck | PushOff | Released
        - StickyRegion.Scope
            - Required
        - StickyRegion.ReleaseBoundary
            - ScopeEnd
        - StickyRegion.PushOff
            - SameLevel
        - StickyRegion.MultiLevelStack
            - Not Core
        - StickyRegion.ScrollHost
            - XYUI-5 ScrollArea
        - StickyRegion.Visual
            - Inherited
        - StickyRegion.Unit
            - DIP via XYUI-0
    - 禁止事项
        - 禁止把 Sticky 当成永久 Fixed Header
        - 禁止 Sticky 修改 Scroll Position
        - 禁止 Sticky Header 越过自身 Scope
        - 禁止下一个 Header 直接覆盖当前 Header
        - 禁止 Normal 与 Stuck 创建两份逻辑节点
        - 禁止 Sticky 激活抢夺 Focus
        - 禁止 Sticky 状态变化清除 Selection
        - 禁止建立 StickyHeader 第二套视觉组件
        - 禁止 Core 默认启用多级 Sticky Stack

- 5.11 · AdaptiveLayout / 自适应布局
    - Ownership Check
        - Existing Upstream Rule
            - XYUI-0
                - 拥有 Density
                - 拥有 Size Constraint
                - 拥有 Min / Max
                - 拥有 DIP
                - 拥有基础 Input / Device Context
                - 未拥有完整 Adaptive Layout Orchestrator
            - XYUI-5.01 Stack
                - 可以接收不同 Direction
                - 不负责决定何时切换
            - XYUI-5.02 Grid
                - 可以接收不同 Track Definition
                - 不拥有 Breakpoint
            - XYUI-5.04 Dock
                - 支持不同 Workspace 结构
                - 不拥有 Adaptive Trigger
            - XYUI-5.06 SplitPane
                - Constraint 无法满足时可以请求 AdaptiveLayout
            - XYUI-5.09 AnchorLayout
                - 不拥有 Breakpoint
        - This Item Inherits
            - XYUI-0 Size Constraint
            - XYUI-0 Density
            - XYUI-0 Input Context
            - XYUI-0 DIP
            - 所有 XYUI-5 Layout Primitive
        - This Item Owns
            - Container-Based Adaptation
            - Constraint-Based Adaptation
            - Layout Variant Selection
            - Adaptive Trigger
            - Stable Variant Transition
        - This Item Must Not Redefine
            - Stack
            - Grid
            - Dock
            - SplitPane
            - Density System
            - Min / Max
            - 组件内部视觉
        - Result
            - NEW + ORCHESTRATION
    - 用途
        - 根据组件实际可用空间选择最合适的布局形式
        - 根据真实 Constraint 判断当前布局是否仍然可用
        - 支持可自由调整尺寸的编辑器 Panel
        - 支持 Desktop
        - 支持 Tablet
        - 支持 Mobile
        - 支持 Dock Resize
        - 支持 SplitPane Resize
        - 支持响应式 Inspector
        - 支持响应式 Settings
        - 支持响应式 Workspace
    - 最终方案
        - Container-Driven Adaptation 为核心
        - Constraint-Driven Adaptation 为核心
        - Named Layout Variants 保留
        - Stable Variant Transition 保留
        - 方案2+3为主要决策模型
        - 方案1负责定义合法布局集合
        - 方案4负责稳定 Variant 切换
    - 核心原则
        - 优先观察组件自己的 Container
        - 不应只观察整个 Screen
        - 真实 Constraint 优先于拍脑袋 Breakpoint
        - AdaptiveLayout 不亲自排列 Child
        - AdaptiveLayout 只选择当前应使用的 Layout Variant
        - 具体排列继续交给 Stack / Grid / Dock / SplitPane 等
        - 每个 Variant 必须本身是合法布局
        - 不得通过不断缩小控件维持一个已经不可用的 Variant
        - 不得在临界尺寸附近反复切换 Variant
    - Container-Driven Adaptation
        - Primary Trigger Context
            - 当前组件 AvailableWidth
            - 当前组件 AvailableHeight
        - 不是
            - 只读取 Monitor Resolution
            - 只读取 Window Resolution
        - 典型
            - 4K Monitor
                - Inspector Width = 240 DIP
                    - 仍应进入 Narrow
            - 普通 Monitor
                - Main View Width = 900 DIP
                    - 仍可以使用 Wide
    - Container Query 思维
        - 每个自适应组件
            - 根据自身 Layout Bounds 判断
        - 优势
            - 同一窗口中的不同 Panel 可以同时处于不同 Variant
        - 例如
            - Viewport
                - Wide
            - Inspector
                - Narrow
            - Hierarchy
                - Compact
    - Constraint-Driven Adaptation
        - 当前 Variant
            - 先进行正常 Measure
        - 如果满足全部 Required Constraint
            - 保持当前 Variant
        - 如果无法满足
            - 尝试下一级合法 Variant
        - 如果仍无法满足
            - 继续寻找更紧凑 Variant
        - 直到
            - 找到合法布局
            - 或进入正式 Failure / Fallback Policy
    - Constraint 来源
        - Child MinWidth
        - Child MinHeight
        - Required Gap
        - Required HitTarget
        - Text Minimum Usability
        - Pane Minimum Usability
        - Aspect Constraint
        - 正式 Component Constraint
        - 全部消费已有规范
    - 典型判断
        - Wide Property Grid
            - Label Min
            - Gap
            - Field Min
            - Action Min
        - 可用 Width 足够
            - 保持 Grid
        - 可用 Width 不足
            - 切换 Compact
        - Compact 仍不足
            - 切换 Vertical Stack
    - Named Layout Variants
        - 用途
            - 定义组件允许存在的合法布局形式
        - 推荐语义
            - Wide
            - Compact
            - Narrow
        - 可以根据具体组件使用其他语义 Variant
        - 但
            - 不得每个组件私自发明十几个类似名称
    - Wide
        - 空间充足
        - 可以使用
            - 多 Column
            - 并排 Controls
            - Expanded Auxiliary Information
    - Compact
        - 空间受限
        - 仍保持主要结构
        - 可以
            - 减少辅助区域
            - 收紧 Track
            - 改变部分排列
        - 不得
            - 破坏 HitTarget
            - 把文字压到不可读
    - Narrow
        - 空间明显受限
        - 可以
            - Horizontal → Vertical
            - Grid → Stack
            - Split → Single Region
            - Side Actions → Secondary Row
        - 重点
            - 改变布局关系
            - 而不是无止境缩小内容
    - Variant 定义原则
        - Variant 表示布局方案
        - 不等于视觉 Theme
        - 不等于 Density
        - 不等于 Device Type
        - 一个手机也可能使用 Wide Container
        - 一个桌面窄 Panel 也可能使用 Narrow Variant
    - Variant Order
        - 组件可以声明
            - Wide
                - FallbackTo Compact
            - Compact
                - FallbackTo Narrow
            - Narrow
                - Final
        - 顺序必须明确
        - 不得形成循环
            - Wide → Compact → Wide
    - Constraint First
        - 如果当前 Variant Constraint 仍然合法
            - 原则上保持
        - 仅仅因为宽度稍有变化
            - 不需要立即切换
        - 优势
            - 减少不必要的 Layout Churn
    - Optional Threshold
        - 允许作为性能优化或设计 Guard
        - 但
            - Threshold 不能替代真实 Constraint
        - 规则
            - Breakpoint 可以帮助快速选 Candidate
            - 最终仍需要验证 Variant 是否合法
    - Stable Variant Transition
        - 目的
            - 避免边界来回抖动
        - 可采用
            - Hysteresis
            - Stable Threshold
            - Constraint Margin
    - Hysteresis
        - 进入较紧凑 Variant
            - 需要达到 Enter Condition
        - 返回更宽松 Variant
            - 需要达到更高的 Exit Condition
        - 示例语义
            - 进入 Narrow
                - 当前布局已无法满足
            - 退出 Narrow
                - 空间恢复到足以稳定承载 Compact
        - 不得
            - 刚刚多出 1 DIP 就立刻切回
    - Stable Selection
        - 当前 Variant 仍合法
            - 优先保持
        - 更宽松 Variant 只有在明显稳定可用时
            - 才允许恢复
        - 目的
            - 防止 Resize 过程中的高频切换
    - Resize
        - Container Resize
            - 重新评估 Constraint
        - 不是每个 PointerMove
            - 都必须产生 Variant Change
        - Variant 不变
            - 正常 Layout Resize
        - Variant 需要改变
            - 执行一次明确切换
    - Stack Integration
        - Wide
            - Direction = Horizontal
        - Narrow
            - Direction = Vertical
        - 决定何时切换
            - AdaptiveLayout
        - Stack
            - 只执行最终 Direction
    - Grid Integration
        - Wide
            - 多 Track
        - Compact
            - 更少 Track
        - Narrow
            - Stack 或单列 Grid
        - Grid
            - 不拥有 Trigger
    - Wrap Integration
        - Wrap 本身已经自然 Reflow
        - 通常不需要 AdaptiveLayout
        - 只有 Layout Pattern 本身需要改变时
            - 才使用 Adaptive Variant
    - Dock Integration
        - Wide Workspace
            - Left + Center + Right + Bottom
        - Compact Workspace
            - 减少同时打开区域
        - Narrow Workspace
            - Side Dock 可以映射到 Tab / Drawer / Single Region
        - 触发
            - AdaptiveLayout
    - SplitPane Integration
        - 正常
            - SplitPane 自行满足双方 Constraint
        - 无法满足双方 Min
            - 请求 AdaptiveLayout
        - AdaptiveLayout 可以选择
            - Split → Tab
            - Split → Single Pane
            - Collapse Secondary
    - AspectContainer Integration
        - 不同 Variant
            - 可以选择不同 Driver
        - 例如
            - Wide
                - WidthDriven
            - Compact Row
                - HeightDriven
    - AnchorLayout Integration
        - 不同 Variant
            - 可以使用不同 Anchor Constraint
        - Breakpoint / Trigger
            - 仍归 AdaptiveLayout
    - ScrollArea Integration
        - 切换 Variant 后
            - 尽量保持 Scroll Position
        - 不得
            - 每次 Variant Change ScrollToTop
    - Focus
        - Variant Change
            - 尽量保持同一逻辑 Focus Target
        - 如果目标仍存在
            - 不得丢失 Focus
        - 如果目标在新 Variant 不可见
            - 转移到合理的可见替代目标
    - Selection
        - Variant Change
            - 不得修改业务 Selection
        - 同一 Item 改变布局位置
            - 仍保持同一 Identity
    - State Preservation
        - 必须尽量保留
            - Selection
            - Focus
            - Expanded / Collapsed
            - Scroll Position
            - Input Value
            - Editing State
        - Variant 只是布局变化
            - 不是组件重建语义
    - Performance
        - 优先
            - 复用现有 Child
            - 改变 Layout Definition
        - 避免
            - 每次 Resize 大量 Destroy / Recreate
        - Constraint Check
            - 应保持轻量
        - 防止
            - Measure → Variant → Measure → Variant 无限循环
    - Variant Loop Guard
        - 同一 Layout Pass
            - Variant 选择必须最终收敛
        - 不得
            - Variant A 导致 B
            - B 又立即导致 A
        - 必要时
            - 使用 Stable Previous Variant
            - Hysteresis
            - Iteration Guard
    - Density
        - AdaptiveLayout 不重新定义 Density
        - Compact Layout Variant
            - 不等于 Compact Density
        - 二者可以独立组合
        - 例如
            - Narrow Layout
            - Comfortable Density
        - 这是合法的
    - Device
        - Device Type
            - 可以作为辅助 Context
        - 但不应成为唯一 Adaptive Trigger
        - 例如
            - Touch Device
                - 可能影响交互 Variant
            - Container Width
                - 仍决定实际布局能否成立
    - Accessibility
        - Variant 切换不得改变内容语义
        - 逻辑 Reading Order 必须稳定
        - 不得因为 Narrow Layout 隐藏必要功能且没有替代入口
        - HitTarget 不得因为空间不足低于正式最小要求
    - 视觉规则
        - AdaptiveLayout 本身不可见
        - Background
            - None
        - Border
            - None
        - Shadow
            - None
        - Variant Change
            - 默认无需夸张 Transition Animation
    - UI代码
        - AdaptiveLayout.Context
            - ContainerBounds
        - AdaptiveLayout.Trigger
            - Container + Constraint
        - AdaptiveLayout.Variants
            - Named Variant[]
        - AdaptiveLayout.DefaultVariant
            - Component Defined
        - AdaptiveLayout.FallbackOrder
            - Ordered
        - AdaptiveLayout.ConstraintCheck
            - Required
        - AdaptiveLayout.Stability
            - Hysteresis
        - AdaptiveLayout.ScreenBreakpoint
            - Secondary Context Only
        - AdaptiveLayout.Density
            - Not Owned
        - AdaptiveLayout.Background
            - None
        - AdaptiveLayout.Border
            - None
        - AdaptiveLayout.Unit
            - DIP via XYUI-0
    - 禁止事项
        - 禁止只看整个显示器宽度决定所有组件布局
        - 禁止 Desktop 永远等于 Wide
        - 禁止 Mobile 永远等于 Narrow
        - 禁止每个组件自行散落大量魔法 Breakpoint
        - 禁止空间不足时无限缩小 Child
        - 禁止突破正式 Min / HitTarget
        - 禁止 Variant Change 清除 Selection
        - 禁止 Variant Change 默认 ScrollToTop
        - 禁止 Variant Change 无意义重建业务状态
        - 禁止 Wide / Compact 在边界反复震荡
        - 禁止 AdaptiveLayout 自己重新实现 Stack / Grid / Dock

- 5.12 · WorkspaceLayout / 工作区布局
    - Ownership Check
        - Existing Upstream Rule
            - XYUI-0
                - 拥有 App 基础结构
                - 拥有 Panel
                - 拥有 Toolbar
                - 拥有 Surface
                - 拥有基础 Layout Token
                - 未拥有完整 Workspace Role System
            - XYUI-5.04 Dock
                - 拥有 Dock Zone
                - 拥有 Dock Group
                - 拥有 Dock Tree
                - 拥有 Panel 当前停靠位置
            - XYUI-5.06 SplitPane
                - 拥有实际二分几何结构
            - XYUI-5.11 AdaptiveLayout
                - 拥有 Layout Variant Selection
                - 拥有 Adaptive Trigger
        - This Item Inherits
            - XYUI-0 App / Panel / Toolbar
            - XYUI-5 Dock
            - XYUI-5 SplitPane
            - XYUI-5 AdaptiveLayout
            - XYUI-0 DIP
        - This Item Owns
            - Workspace Functional Role
            - Workspace Region Contract
            - Primary Work Semantics
            - Canonical Workspace Slots
            - Workspace Mode Composition
        - This Item Must Not Redefine
            - Dock Geometry
            - Split Geometry
            - Panel Visual
            - Toolbar Visual
            - Adaptive Trigger
            - Surface Token
        - Result
            - NEW + COMPOSITION
    - 用途
        - 定义整个应用工作区由哪些功能角色组成
        - 让 Workspace 结构脱离固定左栏 / 右栏命名
        - 建立不同 XYUI 产品之间共享的 Workspace 语言
        - 支持编辑器
        - 支持实验工具
        - 支持生产力工具
        - 支持复杂桌面应用
        - 支持不同 Workspace Mode
        - 支持响应式重新组合
    - 最终方案
        - Role-Based Workspace 为主
        - Primary-Work First 作为核心辅助原则
        - Workspace Slot Contract 作为标准角色集合
        - Workspace Mode Composition 作为高级组合能力
        - 方案1为核心语义模型
        - 方案2保护主任务
        - 方案3统一跨产品 Slot 命名
        - 方案4允许同一产品切换工作模式
    - 核心原则
        - Workspace 首先表达功能角色
        - Workspace 不首先表达物理位置
        - Navigation 不等于 Left
        - Inspector 不等于 Right
        - Utility 不等于 Bottom
        - PrimaryWork 不等于 Center 的死绑定
        - 具体物理位置交给 Dock / SplitPane
        - 具体响应式变化交给 AdaptiveLayout
        - 同一角色可以在不同 Layout Variant 中改变呈现方式
        - 角色身份不得因为位置变化而改变
    - Canonical Workspace Roles
        - GlobalCommand
        - PrimaryNavigation
        - PrimaryWork
        - Inspector
        - Utility
        - Status
        - Transient
    - GlobalCommand
        - 职责
            - 应用级命令入口
            - 全局模式
            - 全局工具
        - 典型
            - Main Toolbar
            - Command Bar
            - Global Search
        - 不是
            - 局部 Panel Toolbar
    - PrimaryNavigation
        - 职责
            - 定位主要对象与内容
        - 典型
            - Hierarchy
            - Map Content Navigation
            - Project Tree
            - Asset Navigation
        - 原则
            - 帮助用户决定“当前在看什么”
    - PrimaryWork
        - 职责
            - 承担当前应用最主要任务
        - 典型
            - Viewport
            - Document Editor
            - Canvas
            - Experiment Result
            - Meeting Main Area
        - 原则
            - 每个 Workspace 必须明确 PrimaryWork
            - 可以包含多个同等级 Document / View
            - 但必须存在清晰主工作语义
    - Inspector
        - 职责
            - 查看与编辑当前上下文对象的属性
        - 典型
            - Properties
            - Inspector
            - Details
            - Tool Settings
        - 依赖
            - 通常响应当前 Selection / Context
    - Utility

        - 支持显示器变化后的布局修复
    - 最终方案
        - Identity-Based Restore 为主
        - Structural Layout Snapshot 保留
        - Validate + Repair Restore 保留
        - Versioned Layout Migration 保留
        - 方案2是核心基础

        - 位置不是身份
        - Child Index 不是身份
        - Dock Zone 不是身份
        - Panel 必须拥有稳定 Layout ID

            - Inspector
                - inspector.properties
            - Map Navigation

            - History
                - history.main

            - 跨启动稳定

            - Active Panel

            - Ratio State
            - Floating State

            - 业务 Document 内容

        - Hierarchical Virtualization 为主
        - Viewport Windowing 作为基础

        - 方案4负责大型 Tree 主模型

    - Hierarchical Virtualization
        - 主应用
            - Tree
            - Hierarchy
            - Map Content
            - Entity Browser
            - Scene Tree

            - Full Hierarchical Data
                - ↓

                - ↓
            - Visible Logical Sequence
                - ↓
            - Viewport Window
                - ↓
            - Realized Visual Rows
    - Full Hierarchical Data
        - 可以非常大
        - 可以包含
            - Root
            - Branch
            - Child
            - Grandchild
        - 不要求
            - 所有节点创建 UI
            - 所有节点参与 Layout
    - Expanded State

            - 自身仍可进入 Visible Logical Sequence
            - Descendants 不进入
        - Expanded Node
            - 其可见 Child 才进入逻辑序列
        - 原则
            - 先解决逻辑可见性
            - 再解决物理 Viewport 可见性

        - 定义

            - Viewport Size

            - Visible Range
            - Overscan Before
            - Overscan After
        - 只 Realize
            - 必要范围

        - 定义
            - Viewport 前后少量预实现区域
        - 目的
            - 高速滚动时减少明显空白
            - 避免刚进入 Viewport 才开始创建导致闪烁
        - 原则

    - Realization Range
        - 包含
            - Visible Items
            - Small Overscan
        - 不包含
            - 远离 Viewport 的大量 Item
    - Visual Recycling
        - 允许
            - Row Visual 离开 Realization Range 后进入 Pool
            - 后续重新绑定其他 Item
        - 优势
            - 减少频繁 Allocate / Destroy
            - 降低 GC 压力
            - 降低 Visual Tree Churn
    - Visual 与 Item Identity
        - Visual
            - 临时表现载体
        - Item
            - 稳定业务身份
        - 必须严格分离
    - Rebind
        - Visual 被重新绑定前
            - 清理旧 Item 临时 Visual State
        - 然后
            - 绑定新 Stable Item ID
            - 读取新 Item 当前正式 State

            - 旧 Hover 泄漏
            - 旧 Selection 泄漏
            - 旧 Expanded 泄漏
            - 旧 Error Visual 泄漏
    - Selection
        - 绑定
            - Stable Item ID
        - 不绑定
            - Row Visual Instance
        - Visual Realize
            - 根据 Selection Set 投影 Selected State
        - Visual Recycle
            - 不得修改 Selection Set
    - Focus

            - 必须独立于 Visual 生命周期

    - Expanded State

        - 不得
            - 绑定 TreeRow 实例
    - Editing State
        - 如果 Item 正在 Inline Edit

        - 优先
            - 保持 Item Realized

            - 正在编辑时 Row 被回收并把 Editor 带到另一 Item

            - 普通 Row
            - Expanded Row
            - Multiline Row
            - Error Detail
            - 不同高度 Item

        - 未测量 Item

        - 目的
            - 允许计算远端逻辑 Offset
    - Measured Size
        - Item 实际 Realize 后
            - 获得真实尺寸
        - 缓存
            - Stable Item ID → Measured Size
    - Size Cache
        - 必须绑定
            - Stable Item Identity
        - 失效条件
            - Item Content 明确改变
            - Density 改变
            - 影响尺寸的 Layout Variant 改变
        - 不得
            - 无变化时每帧重新测量所有 Item

        - Estimated 与 Measured 不一致

            - 新进入 Viewport / Overscan 的节点

            - 展开一个拥有 20,000 Descendant 的 Branch 就立刻创建 20,000 Row UI

        - 已 Realized Descendant

    - Scroll

            - VirtualizedLayout 创建第二套 Scroll System

        - 随后
            - ScrollArea Reveal
    - Insert Item
        - 插入 Viewport 上方
            - 配合 AnchorItem 保持阅读位置
        - 插入远处
            - 不得触发全量 UI 更新
    - Remove Item

            - 回收 Visual
        - 未 Realized
            - 只更新逻辑数据 / Index
        - 如果删除 Anchor

    - Move Item

        - Selection

        - 不得
            - 因为 Index 改变丢失 State
    - Filtering

        - 不要求
            - 为被过滤 Item 创建 Visual
        - Filter Clear
            - 根据 Stable ID 恢复必要 State

            - Item Identity
            - Selection Identity
            - 业务 State
    - TreeNavigation Integration

            - 拥有 Tree Interaction / Row Visual / Expand / Selection Presentation
        - XYUI-5 VirtualizedLayout
            - 拥有大型 Tree Realization Infrastructure
        - TreeNavigation.Requires

    - List Integration
        - List
            - 可以消费 Viewport Windowing
            - 可以消费 Recycling
        - 不要求
            - 使用 Hierarchical Stage
    - DataGrid Integration
        - DataGrid
            - 可以消费 Row Virtualization
        - Column / Cell Visual
            - 仍归 DataGrid

    - Log Integration

            - 由 ScrollArea Position Policy 负责
        - Variable Height
            - 需要多行日志时使用方案3能力
    - Asset Browser Integration
        - 大型 Asset Collection

        - Grid / Thumbnail Virtualization
            - 可以作为后续具体 Collection Layout 扩展
    - Density
        - Density 改变

        - 需要
            - 失效受影响 Size Cache
            - 重新计算 Realization
        - 不得
            - 丢失 Scroll Context
    - AdaptiveLayout
        - Layout Variant 改变
            - 如果影响 Item Size
                - 更新 Size Cache
        - Item Identity
            - 保持
        - Selection
            - 保持
    - Accessibility
        - 未 Realized Item

        - 但
            - Collection 必须正确报告逻辑总量 / Position 等必要语义
        - Keyboard Navigation
            - 可以移动到尚未 Realized Item
            - 随后触发 Reveal / Realize
    - Performance

            - 而不是与数据总量直接相关
        - 禁止

    - State
        - VirtualizedLayout 本身不可见
        - 无独立

            - Selected

            - Focus

            - None

            - 用户不可感知

    - Single Geometry Owner
        - 定义
            - 同一 Child 的同一 Geometry Dimension
                - 只能存在一个 Primary Layout Owner

            - Horizontal Position
            - Vertical Position
            - Width
            - Height
            - Z Plane
        - 可以由不同组件分别拥有不同 Dimension
    - 正确实例
        - Node Editor
            - CanvasLayout
                - 负责 X / Y Position
            - AspectContainer
                - 负责 Preview Width / Height Ratio
            - OverlayLayout
                - 负责 Selection Z Plane

        - 同一 Child
            - Grid.Column
            - Anchor.Left
            - Canvas.X
        - 结果
            - 三个系统同时试图决定 Horizontal Position

    - Parent vs Child
        - Parent Layout
            - 通常拥有 Child Placement
        - Child

        - 特殊 Layout

        - 不得

            - Position Owner

            - Size Relationship Owner

    - Canvas + Anchor

        - Stack
            - 拥有 Cell 内部 Children Flow

    - Dock + SplitPane

        - SplitPane

        - Dock
            - 拥有 Presentation Position
        - 不得
            - 把 Role 与 Position 混成一个 Owner
    - Spacing Ownership
        - 原则
            - 每一段视觉空间必须能够指出 Owner
        - 主要类型
            - Container Padding
            - Sibling Gap
            - Component Internal Spacing
            - Section Spacing
            - Track Gap
    - Container Padding
        - 负责
            - 容器内容与边界之间的空间
        - 典型 Owner
            - Panel Content
            - 正式 Container
        - 不得
            - 内部每一层 Layout 都重新补一圈 Padding
    - Sibling Gap
        - 负责
            - 同一 Parent 下 Sibling 之间间距
        - 典型 Owner
            - Stack Gap
            - Grid RowGap / ColumnGap
            - Wrap ItemGap
            - Masonry Gap
        - 优先
            - 使用 Parent Gap
        - 避免
            - 每个 Child 各写 Margin 模拟 Sibling Gap
    - Section Spacing
        - 由正式 Section Structure 决定
        - 不得
            - Section 外再叠加随机 Margin
    - 实际错误
        - Panel Padding = 12
        - Stack Padding = 12
        - Section Margin = 12
        - Grid Padding = 8
        - 结果
            - Content 实际离 Panel 边缘约 44 DIP
        - 问题
            - 重复 Spacing Ownership
    - 正确结构
        - Panel
            - 拥有 Outer Content Padding
        - Stack
            - 拥有 Section Gap
        - Section
            - 拥有内部 Title / Divider / Content Structure
        - Grid
            - 拥有 Track Gap
    - Spacing Token
        - 全部消费 XYUI-0 Spacing
        - 不得
            - 每个 Layout 创建自己的随意间距体系
    - No Double Spacing
        - 如果 Parent 已提供 Gap
            - Child 默认不得再通过 Margin 添加等价间距
        - 如果 Container 已提供 Padding
            - 内部 Wrapper 不应为了同一目的再添加 Padding
    - Composition Boundary
        - 每一层 Layout
            - 必须有明确独立责任
        - 合法责任例如
            - Scroll
            - Flow
            - Track Alignment
            - Split
            - Overlay
            - Coordinate Space
            - Aspect
            - Adaptive Orchestration
        - 不合法责任
            - 只是为了“多套一层”
            - 只是为了添加 4 DIP Padding
            - 只是因为模板习惯
    - Nesting Governance
        - 允许多层 Layout
            - 只要每层都有独立职责
        - 不得使用固定最大 Nesting 数量作为唯一规则
        - 重点
            - 职责密度
            - 可解释性
            - Measure / Arrange 成本

            - 单 Child Stack 没有 Gap / Alignment 责任
            - Container 只为了增加重复 Padding

            - 或明确其正式责任
    - Performance Guard
        - Layout 变更
            - 只 Invalidates 必要范围
        - 避免
            - 单个 Child 改变导致全 Workspace Measure
        - 大型 Collection
            - 使用 VirtualizedLayout
        - 大型 Canvas
            - 使用 Culling / Spatial Infrastructure
        - 不得
            - 通过大量隐藏 Visual 代替正式 Layout State
    - Measure / Arrange
        - Layout 层级越深
            - 可能增加 Measure / Arrange 成本
        - 因此
            - 无职责 Wrapper 必须删除
        - 但
            - 不得为了减少层数破坏语义边界
    - Hidden vs Removed
        - 需要长期不参与布局
            - 使用正式 Visibility / Composition Rule
        - 不得
            - 创建巨大 Offscreen Layout 模拟隐藏
    - Scroll Composition
        - 默认
            - 一个区域拥有明确主要 Scroll Owner
        - Nested Scroll
            - 只在真实嵌套滚动需求下使用
            - 遵守 ScrollArea Nested Arbitration
        - 禁止
            - 无意义 ScrollArea 套 ScrollArea
    - Adaptive Composition
        - AdaptiveLayout
            - 只决定 Variant
        - 具体 Variant
            - 继续使用 Stack / Grid / Dock 等实际 Layout
        - 禁止
            - AdaptiveLayout 自己演变成万能 Layout
    - Overlay Composition
        - OverlayLayout
            - 只负责层
        - 普通 Child Geometry
            - 仍归实际 Layout
        - 禁止
            - 为了把元素移动 5 DIP 就使用 Overlay
    - Portal Composition
        - 默认
            - 局部 Popup 先尝试正常 Overlay
        - 只有
            - 必须跨 Clip / Layout Boundary
        - 才
            - PortalHost
    - Virtualization Composition
        - VirtualizedLayout
            - 不定义 Row Visual
        - List / Tree / Masonry
            - 拥有实际 Item Layout
        - Virtualization
            - 只决定哪些 Item 被 Realize
    - Layout Diagnostics Requirement
        - 复杂 Composition

        - 必须能够回答

            - Spacing Owner
            - Constraint Owner
            - Adaptive Decision

            - Spacing Owner
