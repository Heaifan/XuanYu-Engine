# XYE EditorShellContext Downgrade Order

- Scope: read-only migration-order analysis on the live checkout; no code changes.
- Existing extraction anchors: `EditorShellControlRefs` already owns UI control discovery; `EditorShellRouteSet` already owns the first Route group. These are the safest first ownership boundaries.
- Recommended order: (0) establish dependency freeze and preserve behavior; (1) move pure selection presenters; (2) move UI control references to the existing control-reference path; (3) move primary route references through the existing RouteSet in functional clusters; (4) move project/domain data (`ContentFiles`, `ProjectInfo`, `WorldState`, `WorldDirtyState`); (5) move tool/input state (`GroundPointerState`, `GroundPlacementState`); (6) move render state (`RenderSeq`, `RenderLastMode`, render-store consumers); (7) move transform appliers; (8) move lifecycle/session ownership last (`Lifecycle`, `SessionActive`, attach/detach/startup/redraw coordination).
- Last-to-move rule: retain `Lifecycle`, `SessionActive`, `RenderSeq`, `WorldState`, and transform appliers until all routes no longer obtain them through the context; they are cross-cutting hubs with bidirectional callbacks and teardown/startup coupling.
- Dependency hub evidence: `EditorShellComposition` constructs secondary routes from context members; `EditorShellCompositionRuntime` reads/writes session/render/domain state; `EditorShellLifecycle` mutates session state and input wiring; `EditorShellEventWiring` consumes UI references and presenters.
- General lesson: downgrade a context by removing ownership, not by merely renaming or grouping fields. Route references can leave early only after the existing RouteSet is treated as the construction boundary; mutable state and lifecycle must leave after their readers/writers are redirected.
