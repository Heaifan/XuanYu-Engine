# XYE-SRP-SLIMMING-R1-0-C-UIVM-AUDIT

- Audit was read-only. The active worktree HEAD (a29c47f2) is post-UiVm migration and does not contain XuanYu.Editor.UI/Vm/UiVm; the last directly auditable UiVm baseline is parent b41d61d3, with terrain behavior additionally evidenced at 2bdc08b2.
- Historical UiVm crossed command routing, canonical/editor state projection, selection commit and viewport picking, mode/workspace transitions, scene/static-model import, terrain source import/runtime activation/cancellation, terrain render cache and auto-framing, notification aggregation, NativeHost lifecycle logging, render projection, and viewport interaction.
- Boundary result: retain UiVm only as a UI projection/adapter and command facade; do not treat it as owner of domain/document/terrain/render-session/lifecycle truth. Target owners in current architecture include EditorEntitySelectionState, EditorShellSelectionSyncRoute, EditorShellContext/routes, Scene3dSessionLifecycle, Scene3dFrameRoute, ViewportPointerPickRoute, SceneDocument transactions, StaticModelAuthoringService, and terrain/world/render owners.
- Migration risk is highest for terrain/import/render interaction because historical UiVm combined async cancellation, domain activation, cache invalidation, camera framing, and presentation refresh in one call chain; medium for selection/mode because projection and canonical truth were already partly separated; lower for pure notification/UI projection.
