# XYE-SRP-R1-A4 Render boundary design

- Boundary model: `SceneStateSnapshot` is generated from authoritative world/render-scene state; `CameraSnapshot` is generated from the camera route before rendering and finalized as presented camera truth after successful Present; `TerrainRenderSnapshot` is generated by terrain/grid/ground-cursor preparation; `RenderSnapshot` is a composition envelope generated by the frame orchestration boundary only.
- Consumers: Vulkan frame preparation consumes SceneStateSnapshot, CameraSnapshot, and TerrainRenderSnapshot to build draw data; picking/gizmo/overlay presentation consume the relevant presented snapshots; diagnostics may consume immutable summaries. UI routes may request or display snapshots but must not mutate render-owned snapshot state.
- Forbidden dependencies: snapshots must not depend on Vulkan Session, GPU handles, CommandBuffer, Swapchain, Frame Gate, Dispatcher, Shell route, WorldState mutable owner, or each other through back references. RenderSnapshot must not own FrameState, Present policy, resource lifetime, or input routing.
- TerrainRenderSnapshot is a future boundary, not an assertion that current code already has terrain render data. Current checkout has grid vertex data and ground cursor state but no first-class Terrain Render Data snapshot.
- Keep `PresentedScenePickSnapshot` and `PresentedNavigationOverlaySnapshot` as domain-specific presented products until an implementation task explicitly defines whether/how they are composed; do not collapse them into a generic snapshot prematurely.
