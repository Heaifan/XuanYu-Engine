## LOG-UX-1-R3 自动滚动修复 + WinExe 控制台输出（2026-07-09 上午）
- **R2 自动滚动不生效**：用户反馈真机运行日志面板根本不自动滚动。
  - **根因**：R2 用 `LayoutUpdated` 事件触发 `ScrollToEnd`，但 Avalonia 的 LayoutUpdated 触发时机与 PropertyChanged(LogItems) 时序不可靠——新日志写入 buffer → RefreshLogBindings → 设置 _pendingScroll=true，但 LayoutUpdated 可能在设置前已触发过、或 ListBox 虚拟化延迟导致不再为本次变更触发。
  - **修复**：改用 `Dispatcher.InvokeAsync(ScrollToTail, DispatcherPriority.Render)` —— 显式放入 dispatcher 队列的 Render 优先级，确保布局完成后再滚，比事件驱动可靠。去掉了 R2 自定义 DispatcherTimerExt 辅助类。Foot.axaml.cs 89→91 行。
- **WinExe 控制台无输出**：用户贴截图显示 `dotnet run` 终端只有 build 输出，Vulkan Console.WriteLine 全部不可见。
  - **根因**：`<OutputType>WinExe</OutputType>` — Windows 上 WinExe 进程不继承父控制台句柄，Console.WriteLine 写入虚空。
  - **影响**：已有 6 处 Console.WriteLine（BridgeLogFormatter.Emit / DeviceOwner.Log / SwapchainOwner.Log / Capabilities.Log / Builder.Log / Selector.Log）全部无效。
  - **修复**：`Program.cs:Main()` 首行调用 `[DllImport("kernel32")] AttachConsole(-1)`（ATTACH_PARENT_PROCESS），零改动 Vulkan 代码。
  - **效果**：关闭编辑器后终端仍显示完整 Detach 释放序列 → 直接解决 T6 审计问题。
- Editor.UI 低内存构建 **0W0E** ✅（Foot.axaml.cs 91 行 / Program.cs 28 行，均 ≤100）。
